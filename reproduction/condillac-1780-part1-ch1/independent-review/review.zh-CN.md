# 独立代码审计：Condillac 有限观察教学模型

## 结论

**通过本次声明范围内的独立审计；未发现尚未修复的实现正确性问题。** 最终统一运行完成于 2026-10-11 13:50 UTC，实际环境为 CPython 3.12.14、Linux x86_64。作者测试、另行编写的 oracle、稳健性测试、变异检测以及命令行核验全部成功。运行普通模式与 `-O` 的确定性 JSON 结果逐字节相同。

这只是一个预先给定有限世界、确定且无噪声观察函数的现代教学模型。审计没有把它当作 Condillac 的历史算法、婴儿认知实验、技能训练结果、心理学因果模型或真实世界正确性保证。一般命题仍依靠主文第 8 节的数学前提和证明，不能由有限测试替代。

本审计由未编写原模型的审查者另行完成，未修改作者代码。作者自己的 `exhaustive.py` 是同一作者编写的对照计算，不能单独当作本次独立审计。这里的“独立”也不意味着零共因：两套检查仍使用同一 Python 解释器和基本整数、元组语义。

## 独立 oracle 的不同结构

代码见 [independent_oracle.py](independent_oracle.py)。它按“世界优先”的顺序生成函数值，为每个查询和值预先建立整数位掩码；历史的预期候选由位与计算。预期结果不调用生产实现的 `candidates`、`outcome`、`signature`、`fiber`，也不导入作者 oracle。

更重要的是，历史不再只由一个真世界产生，而是遍历所有查询和值的组合。因此会直接遇到错误但一致的记录、各条单独合法却互相矛盾的记录，以及值不在某条查询实际值域内的记录。生产构造器先检查值域、再检查一致性；审计也分别核对这两类拒绝及异常类型。

边界为以下四组，所有主枚举历史长度为 0—3，包含重复查询和重复证据：

| 世界数 | 查询数 | 生成用值标签数 | 模型数 | 任意历史数 |
|---|---:|---:|---:|---:|
| 1—4 | 2 | 2 | 340 | 28,900 |
| 1—4 | 0 | 2 | 4 | 4 |
| 1—3 | 1 | 3 | 39 | 1,560 |
| 1—3 | 3 | 2 | 584 | 151,256 |
| 合计 | | | 967 | 181,720 |

某个模型可能没有用到全部生成标签；这正是越出实际值域测试的来源。每一模型标签排列与函数表按声明枚举，不宣称各模型在同构意义下互异。

实际结果：

- 61,128 条合法历史，候选、唯一识别与历史保存均正确
- 67,908 条矛盾历史按 `InconsistentEvidence` 拒绝
- 52,684 条越域历史按 `ValueError` 拒绝
- 61,128 次逆序历史检查，最终候选不因顺序变化
- 343,752 次额外证据延伸检查，其中 184,844 次接受
- 238,608 次“保留候选作为真世界”的真实反馈与拒绝身份配对检查
- 3,036 次完整签名及完整纤维检查

延伸检查是在长度 0—3 的合法历史之后再追加一条记录，并非另称“对所有长度 4 的原始历史做了完整主枚举”。候选真子集与查询当前有区分力的等价性，只对非空、成功接受的分组判断。所有计数有重叠，不是独立统计样本。

## 原作者计数复核

除了重跑作者程序，[check_counts_and_mutations.py](check_counts_and_mutations.py)还用全签名的单元分布及首次出现查询的计数路径复核全部公开数字，未构造 `Model` 或 `Belief` 来计算预期计数。

确认结果为：340 个模型、1,252 个模型—真世界配置、18,780 条真实查询历史、42,568 次逐步转换、20,256 次有区分力转换、42,568 次拒绝检查、1,252 次完整纤维检查、13,080 次有向不可区分伙伴—历史检查。

最后一项另可写成 `15 × Σ[n(n−1) × 4^(n−1)]`，其中 `n=1,…,4`。它计数有向伙伴及重复出现的历史检查，不是 13,080 个不同的无向世界对。42,568 次转换也会重复计算不同序列共有的前缀。当前 README 对这些限制说明正确。

## 状态、输入与错误证据

[test_robustness.py](test_robustness.py)另有 10 个测试方法，普通及优化模式均通过；作者原有 11 个方法、37 个非法输入子案例也都通过。

重点检查结果如下：

1. **普通 API 下深层不可变。** 模型、观察、证据、信念和判断都是冻结 dataclass；嵌套字段仅含冻结对象、元组、字符串或布尔值。递归检查字段赋值和删除均失败，返回候选、签名与纤维为元组。字典、列表、迭代器、嵌套可变值和不允许的子类输入被拒绝，不存在把外部可变映射直接存为观察表的路径。没有声称防御 `object.__setattr__` 或直接改对象内部字典之类故意绕过机制的代码；README 也明确排除了这种保证。
2. **输入边界明确。** 对方法的查询和世界参数追加 99 个非法标签调用，对布尔参数追加 12 个非法调用，并检查 10 个可变或子类输入。空白标签、未知查询、未知世界、错误类型均按约定拒绝。即使拒绝接受观察，参数仍先校验。
3. **一致性不等于真。** 设实际为 A，输入错误但一致的 `q=1` 后，A 被排除；此后一个真实但不充分的 `r=0` 仍可让程序唯一返回错误的 B。再咨询能揭露冲突的查询才抛异常。也就是说，`consult` 生成当前真实值，并不能修复以前接受的假证据，更不能自动恢复已经删除的真世界。
4. **完整纤维不是当前知识。** 即使完整观察签名唯一，尚未接受相应证据时仍不能从当前历史报告唯一身份。零查询时完整纤维是整个域；单元素初始域的“识别”来自模型预设，而非新获取的观察。
5. **重复与顺序边界正确。** 重复证据继续保留在历史中，但不额外缩小候选；重排合法证据不改最终候选，历史对象本身仍保留不同次序。
6. **进展上界是条件式。** 另加九世界、每次选择当前有区分力查询的手工族，确认真实候选保留，最坏例恰经八次严格缩小。这只补充验证第 8.3 节所述条件，不是对任意策略、任意查询总次数或所有模型的穷举证明。

## 优化模式与检查自身的有效性

作者五份 Python 文件的 AST 中均没有 `assert` 语句；其 oracle 使用显式条件抛异常。独立 oracle 同样使用显式 `require`，不会被 `python -O` 删除。两套 unit tests 使用 `unittest` 检查方法，在优化模式下仍运行。

本审计还在独立进程内临时替换五种行为：完全不筛选、忽略拒绝开关、候选不唯一仍返回名字、永远报告不可区分、只保留最新证据。五种变异都被独立 oracle 捕获，普通和优化模式的检测结果一致。替换后立即恢复原方法，没有修改作者文件。它说明检查确实对这些错误敏感；不意味着能捕获所有可能的故障。

`walkthrough.py` 与 `exhaustive.py` 从无关工作目录执行成功。`verify.py` 在目录名含空格的临时副本中、从无关目录执行成功，生成自己的真实日志，未覆盖作者现有日志。包内源码、审计源码均编译通过；未实际运行 Windows 或其他 Python 版本，因此不把这次结果扩展为跨平台实测保证。

## 发现与修订复核

初读时报告了两项文档问题，最终版本均已修正，并已复读确认：

- 第 9 节原有教学附件和结果链接指向不存在文件；现已指向 `README.md` 与实际 `logs/exhaustive.json`。
- 第 8.5 节原表述把“永久拒绝某一条能区分的查询”写成足以保持不可区分。反例是拒绝查询 q，却接受另一条也能区分的查询 r；程序仍可识别。当前主文已要求拒绝一切能区分该对候选的证据，且不接受其他区分证据，并明确说明仅拒绝一条不够。独立测试保存了这个反例。

另外核对了主文与实现之间的范围说明：数学表述允许一般初始候选子集，而 API 初始域固定为整个 W；数学交集可以为空，而 API 对不相容历史抛异常并保留旧状态。第 9 节现在明确公开这两点，不把异常当成成功识别。接受证据的下标与拒绝交互前后的下标也已分开。

没有留下需阻止发布的代码缺陷。假证据、观察噪声、世界变化、域外真值、查询成本、学习观察函数、心理技能增长等仍不在实现范围内；这些是公开模型边界，不是测试通过后可以略去的前提。
