# I.30 独立代码审核

## 方法与结论

审查者没有编写生产模型。独立阅读 `model.py`、`test_model.py`、`demo.py` 与 README，另写 [check.py](independent-review/check.py) 用 Floyd–Warshall 距离矩阵作 oracle，而不复用被审函数的队列搜索逻辑。结果在本次有界输入覆盖内通过，没有发现阻止发布的实现错误。它不是通用证明器或经验事实核验器。

## 实际执行

从本目录分别执行：

```sh
python3 independent-review/check.py
python3 -O independent-review/check.py
python3 -OO independent-review/check.py
```

三种模式各自的真实输出为 [normal](independent-review/normal.log)、[-O](independent-review/O.log)、[-OO](independent-review/OO.log)，退出状态均0。每种模式：

- 三个项的九条可能有向边（含自环），每条取缺失／verified／endoxon，共19,683个着色图。
- 两种模式与全部九个有序目标对，共354,294次查询。
- 214,326条返回证书：核最短距离，并逐边独立核ID、方向、类别及终点；亦调用公开检查器比较。
- 139,968个无路径查询：依据独立可达矩阵构造单对象反模型，逐次确认前提成立而目标失败。
- 18项坏输入抛出ValueError，涵盖空项表、重复项/ID、未声明项、非法模式/标签/出处、非法证书、空论域、缺外延、域外对象及非法观测。
- 另核错序、缺边、伪ID、错误模式边、错误空证书和未到目标的循环证书均被拒；合法循环证书及自反空证书被接受；模式间不偷偷互用材料。

模型自带23项单元测试及64种二对象解释的日志也已检查；独立oracle不是重复把生产函数当作期望值生成器。以上计数只描述实跑的有限集合，不能单凭穷举推广到任意大小的图或对象域。

## 代码语义和边界

- 输入校验使用显式异常，不用assert；优化模式不取消这些检查。
- 查找的seen集合避免环重复入队；每次扫描前提保留输入顺序，因此等长路线依输入顺序择一，不保证枚举全部证明。
- 证书检查器允许合法非最短路径甚至环；这是路径合法性与最短搜索的不同职责，不是漏洞。
- 两个标签库分离是声明的教学策略，不认证古代意见或现代事实；出处字段只保留文本。
- 解释函数只核所选标签前提；标签未选中的前提不被悄悄当作语义约束。无路径反模型同样相对于所选库。
- 当前实现为逐节点扫描全部边，不是邻接表；正文已据反馈明确边扫描量O(|V||E|)。严格总成本还包括校验、节点成员查询与路径元组复制。
- 输入检查不是任意恶意对象的安全沙箱；本模型只接收文档约定的Python数据。没有网络或文件写入功能，没有自动证明领域事实的能力。
