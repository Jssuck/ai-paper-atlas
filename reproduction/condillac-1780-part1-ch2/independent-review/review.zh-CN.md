审计日期：2026-10-11。对象为本包最终版本的五份生产 Python 源码及对应中文说明。复核由未编写生产模型的另一审计执行者完成；这不是第三方学术同行评议，也不是历史实验复现。

**结论：在列明的输入规格和核验范围内通过。** 发现并修复了优化模式下验证语句可能失效的问题；最终生产代码未发现尚未解决的关系求解正确性缺陷。一般数学结论依据证明，有限运行只提供实现证据。

## 2. 不同算法的交叉核验

生产算法按图传播坐标。审计另写 [audit_model.py](audit_model.py)，将每条边写为系数矩阵的一行，以 `Fraction` 做精确行最简形消元：

- 方程是否相容，由增广矩阵的矛盾行判定。
- 查询的系数行是否属于约束行空间，决定差值是否可识别；消元同时取得被识别的值。
- 矩阵秩给出分量数和整数平移参数数目的独立交叉检查。

该判据不调用生产图遍历、向量辅助函数或相容性判定。这里在有理数上消元是适用的：差值图若有解，分量内沿整数边取路径和便有整数代表；其自由变化为整数分量平移。因此不会将“只有非整数解”的一般线性系统情况混入本规格。

常规与 `-O` 的结果相同，每种模式覆盖以下范围，重复运行不翻倍算成新输入：

| 范围 | 图数 | 相容图数 |
| --- | ---: | ---: |
| 三对象、一维；每对缺边或偏移为 −2 至 2 | 216 | 110 |
| 三对象、二维；每对缺边或偏移为 {−1,0,1}² | 1,000 | 320 |
| 四对象、一维；每对缺边或偏移为 −1、0、1 | 4,096 | 1,040 |
| 另列边界、多重边、三维及不完整对象集 | 39 | 36 |
| 合计 | 5,351 | 1,506 |

合计另有 3,845 个不相容输入。每次执行 21,337 次有序对象查询和 8,884 次已实例化边方程核对。前一数字包括自查询和未观察对象的查询，与作者的 1,290 次“相容三对象图内不同无序对象对查询”定义不同，不能混加。

另写 35 条非法输入操作检查，并验证成功/失败操作均不修改原账本、位移参数映射不被修改、返回字典和汇总列表不与内部状态共享可变内容。账本和边的数据类冻结；输入名称、整数类型、维数及端点归属按规格拒绝异常值。

具体结果见[常规矩阵核验](logs/matrix-audit-normal.json)与[优化矩阵核验](logs/matrix-audit-optimized.json)。

## 3. 主张、边界和数值核对

### 3.1 对象、关系及所有解

逐项复核了方向符号、负数、反向记录、重复记录、相容冗余边、矛盾平行边、零/非零自环、循环冲突、多个分量、未观察对象、单对象和空观察状态。三维案例含绝对值为 $`10^{120}`$ 的整数，未使用浮点近似。

原始对象清单非空，但已观察集合可空。空观察时只有空映射这个已观察解，零个分量、零个已观察平移参数；这不表示目标清单已经覆盖。未观察对象不会被暗中赋零，其自查询也按接口返回未知。

结构论证也被单独检查：有解时，任意两解之差沿每条边相等，故在每个连通分量上为常量；反之，各分量独立加任意整数向量仍满足全部边。这证明解族恰好是分量平移，并解释相对可识别性。记录正确与否仍需外部证据；矛盾见证不自动认定哪条边来自错误观察。

正文用一维手算，代码推广到固定轴向的 $`\mathbb Z^k`$，每个坐标独立应用同一差值条件，推广成立。代码没有自动辨认对象、未知旋转/尺度、物体不重合、噪声或绝对位置约束；添加这些假设需要另改模型。仅有方向位移，不能偷换成无方向距离。

### 3.2 有限盒子的界限

三顶点图的简单路径至多两条边，因此每坐标边绝对值上界为 $`M`$ 时，把各分量的根设零，可在 $`[-2M,2M]`$ 内得到一个代表解。作者一维取 $`M=2`$、二维逐坐标取 $`M=1`$，存在性枚举范围足够。

断开时，任何非单点分量至多两点，归零后的跨度每坐标不超过 $`M`$。固定 A 为零后，任取不含 A 的一个分量，还能在一个坐标上平移 1 而留在盒中；这样跨分量差值至少出现两个值。故在所列三对象族内，有限盒也不会制造虚假的跨分量唯一性。这个余量论证不自动适用于更大的图或其他盒子。

### 3.3 独立重算公开数字

一维相容图数按边数分解为 $`1+3\cdot5+3\cdot25+19=110`$；最后 19 是完整三角形满足路径和的偏移三元组数。二维对应 $`1+3\cdot9+3\cdot81+7^2=320`$。所以 1,216 图中相容 430、不相容 786，与实跑一致。

赋值代入次数为 $`216\cdot81+1000\cdot625=642496`$；对象对查询为 $`430\cdot3=1290`$；全图反向检查 1,216 次。还核对了四条边的 24 种排列、矛盾三角形的 6 种排列，以及前缀账面分数集合 {6,7,8,9,10,11}。正文、README、MODEL 和走查中的这些数值没有发现不一致。

## 4. 故障注入和已修复问题

### 已修复：优化验证失效

初稿走查与穷举使用裸 `assert`。注入明显错误的查询结果或参考坐标后，普通运行拒绝，`-O` 和 `-OO` 却正常返回，暴露“通过”可能没有实际验证的缺陷。初稿统一执行器也未将优化标记传给子进程。

作者已改为显式 `require`，并转发优化级别、分开保存各模式日志。复测两个错误注入探针，在普通、`-O`、`-OO` 六次调用中全部被拒绝。[初稿故障证据](logs/initial-fail-open-evidence.json)保留当时源码哈希和实际观察，不是最终代码的失败；[修复后证据](logs/fixed-guard-probes.json)绑定最终文件。初稿源码副本未保留在发布目录。

附带修复：`anchor_unresolved` 现在对错误账本类型明确抛 `TypeError`；复杂度文字已区分完整清单扫描、排序、固定维数和整数单位成本假设。

### 六个受限模型变异全部检出

审计只在内存副本分别注入：反向边不取负、差值符号倒置、忽略矛盾、忽略断开、平移参数漏乘维数、隐藏未观察对象。六个变异在普通及优化模式均被独立核验检出。它们说明对应防线确实能发现这些错误，**不是全面变异覆盖率或所有可能缺陷均已排除的证明**。

## 5. 重跑与限制

在本包根目录可运行：

```bash
python3 independent-review/audit_model.py
python3 -O independent-review/audit_model.py
python3 independent-review/verify_validation_guards.py
python3 independent-review/audit_execution.py
```

第一、二条和探针输出 JSON 到标准输出；执行审计还更新自己的最终代码哈希与测试日志。脚本也支持用绝对路径从包外启动。变异只发生在内存，执行副本位于临时目录并在结束后清理。若生产代码被修改，应重新执行并更新证据，旧哈希不能代替重审。

未做跨 Python 版本/跨操作系统矩阵、性能基准、大规模压力测试、外部历史文本校勘或人类心理实验。本审计不认证原文的认识论、视觉容量、练习效果或“唯一方法”主张。一般图定理与有限代码检验、内部自洽与观察真实性，均继续分开。
