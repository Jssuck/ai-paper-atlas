# 中文逐步走查

这是虚构的现代教学例子，不是孔狄亚克的实验或算法。先运行 `python3 -B demo.py`，再按下列顺序手算。所有分数都保持精确，不用浮点近似。

## 1. 先固定你在数什么

行动集合为 `withdraw`（退避）、`stay`（停留）、`approach`（接近）。我们只跟踪退避的习惯指数；$`u=1`$表示本步退避，$`u=0`$表示本步没有退避。$`u=0`$不表示“没有任何动作”，更不表示道德错误。

取$`\alpha=1/2`$、$`h_0=0`$，给出五步实际动作：

```text
withdraw, withdraw, withdraw, stay, stay
```

`action_inputs` 转成 $`(1,1,1,0,0)`$。递推 $`h_{t+1}=(h_t+u_t)/2`$：

1. 第一次退避：$`(0+1)/2=1/2`$。
2. 第二次退避：$`(1/2+1)/2=3/4`$。
3. 第三次退避：$`(3/4+1)/2=7/8`$。
4. 第一次停留：$`(7/8+0)/2=7/16`$。
5. 第二次停留：$`(7/16+0)/2=7/32`$。

输出 `habit.trace` 为 $`(0,1/2,3/4,7/8,7/16,7/32)`$，共六个数，包含未行动的初始状态。

闭式再算一次：$`n=5`$、$`h_0=0`$，只前三项有贡献，

```math
h_5=\frac12\left[\left(\frac12\right)^4+\left(\frac12\right)^3+\left(\frac12\right)^2\right]
=\frac12\left(\frac1{16}+\frac18+\frac14\right)=\frac7{32}.
```

这验证两条计算路线一致；它没有测得一个人的真实自动化程度。

## 2. 用反例检查“总次数足够吗”

从0出发：

- 输入 $`(1,0)`$：$`0\to1/2\to1/4`$。
- 输入 $`(0,1)`$：$`0\to0\to1/2`$。

同样只退避一次，末值却不同。差$`1/4`$正是$`\alpha^2`$。不要先把输入排序再求状态，否则丢失时间信息。变异检查正是用这类非回文记录发现闭式权重的方向错误。

连续执行八次得$`255/256`$；从$`h_0=1`$连续不执行八次得$`1/256`$。两者接近端点但不等于端点。无限极限的理由是模型中的几何幂衰减，而非程序跑了八步。

进阶手算：输入 $`(1,0,1,0,1,0)`$ 时，状态依次为 $`(0,1/2,1/4,5/8,5/16,21/32,21/64)`$。偶数步与奇数步趋向不同值，不能把半数执行直接写成$`h=1/2`$。

## 3. 可见退避，究竟看见了哪个意向？

现在另开一组辨别探查，共用相同行动名字；不要把这些探查逐步对应到上一节的五步练习记录。

$`\pi`$表规定三个意向在`alarm`（警报）、`quiet`（安静）、`invitation`（邀请）中的动作：

- `fear_harm`（怕受伤）：退避、停留、接近。
- `desire_quiet`（想清静）：退避、退避、退避。
- `desire_rest`（想休息）：退避、停留、停留。

这些只是人为指定的行，不声称真实害怕的人在邀请时必然接近。模型先假定真实意向包含在此候选表内，而且探查中不变。

逐条增加观测：

1. 尚无观测：三个候选都相容。
2. `alarm`下退避：三行首项都一样，仍是三个候选。
3. 再见`quiet`下停留：排除想清静，留下怕受伤、想休息。
4. 再见`invitation`下接近：只有怕受伤一行匹配，得到单个候选。

与输出`inference.candidates_by_prefix`对应。注意第二步已经“看见了行动”，但并未唯一看见其意向；第4步的唯一性仍以表格正确为条件。

等价类也逐步细化：

- 只用 `alarm`：$`\{\text{怕受伤},\text{想清静},\text{想休息}\}`$。
- 用 `alarm`、`quiet`：$`\{\text{怕受伤},\text{想休息}\}`$ 和 $`\{\text{想清静}\}`$。
- 三个情境全用：三个单元素类。

再观察一次`alarm`下退避不会继续细分。若另一种意向被加进来、在三个情境上全都复制怕受伤一行，这两个候选将无法由当前表区分。

## 4. 两种失败必须分开

第一种：在确定表下记录`alarm`时既退避又停留，相容集为空。输出`contradictory_record`是空列表。它报告观测与模型不一致，没有宣称被观察者“没有心灵”。现实的动机变化或观测噪声都可能要求修改模型。

第二种：观察者把自己的动作表直接套给另一个人，而那个人恰好把“怕受伤”和“想清静”两行对调。那个人想清静时产生退避、停留、接近；观察者会唯一判断为怕受伤。

这是`transfer_counterexample`：目标真实候选是`desire_quiet`，错误迁移得出的候选是`fear_harm`。空集能暴露有些冲突，单元素集合却不能保证发现表格迁移错误。原文诉诸自身经验的步骤，需要单独讨论它凭什么适用于别人。

## 5. 同一动作和高习惯指数，能否自动判为“好”？

前三次退避后$`h=7/8`$。五步练习记录中实际出现过退避、停留，所以$`F=\{\mathrm{withdraw},\mathrm{stay}\}`$。先只把$`F`$当作“曾观察到”的描述集合。

对$`A`$的三个动作共有$`2^3=8`$套二值规范代码，包括空代码和全代码。空代码在这里意为三个动作都不合规；它不是“没有规则可讨论”。候选代码族为空，才是没有任何代码满足前提，两者完全不同。

没有额外约束时，可以选：

- $`C_1=\{\mathrm{stay}\}`$：退避不在其中。
- $`C_2=\{\mathrm{stay},\mathrm{withdraw}\}`$：退避在其中。

两套代码共有同一$`F`$、$`h`$和动作记录，却对退避给出相反评价。输出`withdraw_unconstrained`为`underdetermined`。这说明当前输入缺一条规范连接，不是已经证明任何自然法都不可能。

## 6. 把额外前提写出来再计算

先规定$`R=\{\mathrm{stay}\}`$必须合规，$`Q=\{\mathrm{approach}\}`$必须不合规。这两个额外规定是教学设定，没有冒充从人的需要和能力推出来。

只剩退避自由选择，因此恰有两套代码$`C_1`$、$`C_2`$。此时：

- 停留：`all_permit`。
- 接近：`all_forbid`。
- 退避：`underdetermined`。

“停留的判断确定了”并不意味着完整代码只有一套。若再把退避加入$`R`$，候选代码才唯一成为 $`\{\mathrm{stay},\mathrm{withdraw}\}`$；退避返回`all_permit`。若把退避同时放入$`R`$和$`Q`$，则候选代码为零套，返回`inconsistent`，不能说“所有代码都同意许可”。

原文还给出了自然、需要、能力和上帝的正当化链条。代码没有包含这些前提，因此不能用以上任意设定代替原文的结尾，更不能把本示例的两套规范误称为对作者自然法体系的完整反模型。

## 7. 怎么读取验证结果

运行 `python3 -B verify.py`。最终应看logs/verification.json的status和每项`exit_code`，而不是只看文件存在。

- unit-tests-normal、unit-tests-O、unit-tests-OO：每种模式27个测试方法。
- finite-oracle三个模式：同样的有限边界，不是三倍独立证据。
- demo三个模式：JSON文本完全相同。
- valid-semantic-mutations-OO：10个语法有效错误在优化模式下确实触发测试检查失败，没有通过语法错误或导入错误蒙混计数。

logs/mutations-initial.json保留初轮结果：闭式权重反转曾逃过单元测试，原因是当时单独核闭式的非空序列 $`(1,0,1)`$ 是回文。随后在同一个测试方法中加入 $`(1,0)`$、$`(0,1)`$ 的闭式精确值。看logs/mutations.json及最终verification.json确认修补后的结果，不要把初轮FAIL当作当前失败，也不要删除初轮把检查过程装成从未发现问题。

有限oracle检查所有所列小模型；大规模或现实对象的结论仍须靠明确前提及证明。本程序不需要Notebook，也没有任何Jupyter运行声明。

## 8. 自测与答案

1. $`h_0=1/4`$、$`\alpha=2/3`$，输入 $`(1,0,1)`$，末值多少？
   答：$`1/4\to3/4\to1/4\to3/4`$；闭式也得$`3/4`$。
2. 没有观测时，非空候选集是否自动只有一个？
   答：不，全部候选都相容；仅当原候选集本来就是单元素才唯一。
3. 增加情境是否总能严格减少等价类大小？
   答：不。新情境给所有旧候选同一动作时，分区不变。
4. $`h`$很大能否排除代码$`C_1`$？
   答：不能；模型中$`h`$与规范代码没有这种桥梁。
5. 3个动作、$`R`$和$`Q`$各含一个且不同，代码有几套？
   答：$`2^{3-2}=2`$。
6. 所有三个动作都纳入$`R`$、$`Q`$为空，结论是什么？
   答：唯一代码$`A`$，三个动作都在此指定代码下合规；这仍不证明该代码正当。
