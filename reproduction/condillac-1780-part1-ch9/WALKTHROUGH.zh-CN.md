# 从一声 do 到一段旋律：逐步读懂模型

这里的音乐符号只是容易辨认的标签。实验不需要乐理、机器学习框架、训练数据或网络。先执行 python3 demo.py；完整输出保存在 logs/demo.json。

## 1. 先把“发生着”与“可以再发生”分开

原文印刷页 83–85 反对把记忆想成装满当前不用的观念的仓库，用乐器停止发声、再次演奏又产生声音作类比。

程序也分成两个层次：

- active 是现在激活的一个 IdeaEvent
- 三个习惯表保留以后如何响应的条件

调用 clear_active() 后，active 变成 None，而表中的边与强度不变。返回给实验者的历史日志依然可以看见过去事件，这不表示回放算法查询了这些日志。

这个区分只是一种程序设计上的对应。程序仍保存符号化的倾向，不能从一个 Python 对象删除操作推出关于灵魂或表征本体的结论。

## 2. 练两遍 do、mi、sol

```python
from model import SequenceMemory
memory = SequenceMemory()
memory.practice(["do", "mi", "sol"], repetitions=2)
result = memory.replay("do")
print(result.tokens, result.stop, len(result.decisions))
```

实际输出：

```text
('do', 'mi', 'sol') end 3
```

逐步变化如下：

1. 第一遍形成 do→mi、mi→sol、sol→END，每条强度 1。
2. 第二遍把这三条边的强度都变成 2。
3. 提示 do 已在输出中，第一次判定唯一选择 mi。
4. 第二次唯一选择 sol。
5. 第三次唯一选择 END，回放结束。

END 是学到的终止倾向；它不是“表里没有其他东西”的默认猜测。因此输出三个符号，需要三次判定，而不是两次。

强度是正整数，不是概率，也不是反应时间；程序没有根据练习次数预测真实演奏速度。

## 3. 同一个提示，可以属于不同的曲子

继续训练 do、fa、la 两遍。现在 do 的这一行出现：

- do→mi：2
- do→fa：2

两者并列，程序返回 tokens=[do]、stop=ambiguous、decision_count=1。它不会按字母顺序挑一个假装记对了。

再练 do、mi、sol 一遍，do→mi 变为 3，do→fa 仍为 2。于是重现 do、mi、sol。

这解决了数值并列，仍然没有知道实验者想听哪首曲子。如果实验者此刻想听 do、fa、la，选更熟的曲子就是答非所问。正确标签“频率优势”不等于“意图理解”。

## 4. 上下文修复的是哪一种冲突？

```python
memory = SequenceMemory()
memory.practice(["do", "mi", "sol"], context="piece_A")
memory.practice(["do", "fa", "la"], context="piece_B")
print(memory.replay("do", "piece_A").tokens)
print(memory.replay("do", "piece_B").tokens)
```

实际输出：

```text
('do', 'mi', 'sol')
('do', 'fa', 'la')
```

因为程序查的键分别是 (piece_A, do) 与 (piece_B, do)，它们已不是同一行。曲名由调用者明确提供，系统没有从 do 自动推断曲名。

反例：只练一条 A、B、A、C，且上下文固定为 one_piece。A 仍被要求先接 B、后接 C。当前键两次都是 (one_piece, A)，无法知道自己在第几次 A，结果仍是 ambiguous。

加一个曲名不是普遍补救。若要保留位置，须增加状态并说明谁维护它；否则就是把缺失的信息偷偷补进算法。

## 5. 练习与遗忘是两个显式操作

把 A、B 练三遍，形成 A→B 与 B→END，两条边强度都是 3。

- forget(2) 后，两条边都为 1，仍恢复 A、B，并以 end 结束
- 再 forget(1) 后，两条边删除；提示 A 只能返回 [A] 与 missing

这里没有真实时间单位。它说明“若规则设为减法，强度会怎样改变”，没有估计某个人过多久会忘。

同一行所有边一起减同一值时，原本的严格胜者不会被较弱边反超。因此这个演示只展示减弱与删除；共享提示的竞争和容量淘汰是另外两个干扰来源。

## 6. 两条边的容量，装不下三条必要关系

设置 capacity=2，练习 A、B、C：

1. 加入 A→B，强度 1
2. 加入 B→C，强度 1
3. 加入 C→END 后出现三条边，超过上限
4. 三条同样弱，删除最早加入的 A→B

因此日志显示 edges=2，提示 A 的回放为 [A]、missing。

容量规则是“每张表的边数上限”，不是能记住几首曲子的上限。一个长度为三、符号互异的目标，单是中央表就需要三条边，其中包含 END。

更微妙的失败：如果已有两条强度 10 的边占满容量，新边强度每次只加到 1 就立刻被淘汰。无限重复也未必积累成功。这个模型的容量规则有自己的局限，不能把“多练总有用”当成普遍定理。

## 7. 有些次序一旦没有保留，就无法补算

比较两段训练：

- A、B、A、C、A、B、A、C、A
- A、B、A、C、A、C、A、B、A

它们经历的次序不同，但学到的五种边、各边次数、首次插入顺序完全一致。demo.json 中：

```json
{
  "equal_snapshots": true,
  "equal_birth_metadata": true,
  "equal_serial": true
}
```

从完全相同的保留状态和提示出发，任何确定性程序都只能输出同一答案，不能保证分别还原两个不同原始次序。换一个更复杂的检索算法，也不能凭空找回已经丢失的信息。

这就是 MODEL.zh-CN.md 中的信息丢失证明。它比“当前程序恰好猜错”强，但仍然只针对这个记忆编码方式，不是说一切记忆系统都无法保存顺序。

## 8. 把感觉、回放和动作反馈接起来

```python
from model import EmbodiedMemory, Observation, Signal
agent = EmbodiedMemory()
agent.teach([
    Observation("do", Signal("hand", "do")),
    Observation("mi", Signal("hand", "mi")),
    Observation("sol", Signal("hand", "sol")),
], repetitions=2)
agent.sense(Signal("hand", "do"))
trace = agent.recall()
print([(e.idea, e.source) for e in trace.events])
body = trace.outputs[-1]
print(agent.feedback(body).event)
```

实际的事件顺序：

```text
[('do', 'external'), ('mi', 'replay'), ('sol', 'replay')]
IdeaEvent(idea='sol', source='feedback')
```

teach 分别学了三类关系：信号到符号、符号到后继、符号到身体信号。感官提示只输入 do，后两个符号来自内部续接。最后一个身体输出再送回传入通路时，来源标签是 feedback。

这种反馈可能对应真的身体感觉，但不是独立外部对象的新证据。程序没有从内容 sol 自动判断它来自哪条路；标签直接由调用路径设定。若调用者把同一反馈信号直接传给 sense，它仍会标成 external。这个演示提供可检查的因果路线，而不是不可伪造的来源监控。

原文 pp.88–90 强調脑与器官的共同作用。程序将路径分开，是为了展示依赖关系；不是把所有器官过程都还原为同一个字符串，也没有模拟真实的手指与耳朵动力学。

## 9. 关闭接口时，什么会变？

- afferent_enabled=False：新的 sense 或 feedback 被阻断，active 清空，状态为 blocked
- efferent_enabled=False：中央回放仍可产生符号，身体输出全部为空
- clear_active()：只清除当前事件，保留学到的习惯
- forget(d)：三个习惯表都减弱，当前激活本身不因此立即消失

中央回放不强制要求每一步成功发出身体输出，这是本教学实现的一项选择。不能用它证明原文的感官—脑相互依赖可以忽略。

如果从未设定当前提示就直接 recall，程序会报错，不会默默发明起点。

## 10. 预算为何必要？

若实验者直接教出 A→A，而不提供能胜出的 END，回放没有自然终点。设 max_transitions=3 会得到：

```text
tokens = A, A, A, A
stop = budget
decision_count = 3
```

提示 A 已先出现，三次转移再增加三个 A。budget 不等于 end；它表示实验者停止了计算，不表示系统记住了曲子结尾。

## 11. 已回答的练习

### 练习一：忘记当前事件，为什么还能再想起？

答：clear_active 只修改 active。下一次提示仍然可以读取中央与外围习惯表，生成新的事件。程序没有让旧事件从仓库里搬回现在；但表本身仍保存现代的符号化信息，哲学解释必须保持这个区别。

### 练习二：只训练 A、B、A、B，足够多次后会精确结束吗？

答：不会。A 的后继总是 B，但 B 同时有 A 和 END 两个同频后继，回放到第一个 B 就发生歧义。即使人为偏置为 B→A，固定一阶规则也只会进入循环；偏置为 END 则过早结束。

### 练习三：把同一提示的竞争边各减一，能让较弱边反超吗？

答：不能。两个正值同时减一时差不变；较弱边先归零后也不会变成胜者。若需要模拟选择性干扰，必须另加机制并披露新假设。

### 练习四：为什么信息丢失例子还要比较插入序号？

答：有限容量的淘汰依赖边的年龄。相同次数但不同首次出现顺序，未必代表完整内部状态相同。我们使用的两段历史使次数、边年龄和下一个序号都一致，排除了从元数据恢复次序的漏洞。

### 练习五：上下文是不是偷偷保存了答案？

答：上下文确实提供额外信息。区分曲目标签可合理表达外部线索；若每个位置都给一个唯一标签，则把次序信息外置了。应说明标签来源、维护成本和用户必须提供多少信息，不能把恢复率改善当成免费收益。

### 练习六：为什么测试要用 unittest.assertEqual，而不是普通 assert？

答：Python 的 -O 和 -OO 会移除普通 assert。若关键测试只用它们，优化模式可能“全过”却没有检查。当前测试使用 unittest 断言方法，突变检查还用 AST 验证测试源码没有裸 assert。

### 练习七：删除一个 import，让测试跑不起来，算检出错误吗？

答：不算语义行为检出。突变框架要求完整的 40 个测试 ID、全部实际执行、至少一个断言失败且没有运行错误，才记为 behavioral_kill。语法、导入、空套件、运行异常各有独立控制，不能伪装成通过了抗错验证。

### 练习八：这个模型说明 Condillac 发明了序列学习或现代神经网络吗？

答：没有。它说明原文提出的一组结构问题能被现代工具清晰重构，并揭示一个极简重构的能力和失败条件。历史上的概念关系、直接影响与发明优先权，需要另外的文本和历史证据，不能由程序演示推出。

## 12. 合理的后续扩展

若继续做实验，优先一次只改变一个假设：

1. 把固定上下文改为显式可更新的历史状态，检查哪些重复模式仍会碰撞
2. 比较不同的容量淘汰规则，记录同样训练次序下的差别
3. 让感官信号含噪声，并把“收到外部输入”与“正确识别外部对象”分开计分
4. 用真实实验资料评价一个明确限定的心理学预测；在获得证据之前，仍标为未验证重构

这些扩展当前均未实现。原文提醒读者不要假装解释自己不知道的机制，恰好也是使用这类小模型时最重要的约束。
