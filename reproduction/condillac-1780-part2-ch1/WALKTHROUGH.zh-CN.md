# 从手算到运行：不要把相互支持当作新观察

以下情节和标签都是本次原创教学例子，不是原书案例。先预测输出，再运行 `python3 -B demo.py`；完整输出保存为 logs/demo.json。原典范围是 1798 年版《La Logique》第二部第一章，印刷页 96–108。

## 1. 两条观察究竟增加了什么

我们给一个理想化小物块设三个候选标签：copper、iron、wood。它们仅用于演示集合筛选，相容表由我们预先规定，不是程序进行真实物理测量的结果。

令 $`H=\{\mathrm{copper},\mathrm{iron},\mathrm{wood}\}`$，$`C_{0}=H`$。约定真实候选是 iron。

1. 第一次观察相容于 $`E_{1}=\{\mathrm{copper},\mathrm{iron}\}`$。$`C_1=C_0\cap E_1=\{\mathrm{copper},\mathrm{iron}\}`$。wood 被排除，但留下两个候选。
2. 第二次观察相容于 $`E_{2}=\{\mathrm{iron}\}`$。$`C_2=C_1\cap E_2=\{\mathrm{iron}\}`$。现在候选唯一。
3. 反过来先处理 $`E_{2}`$，轨迹为 $`H\to \{\mathrm{iron}\}\to \{\mathrm{iron}\}`$。中间状态不同，最终相同。
4. 如果只反复处理 $`E_{1}`$ 三次，轨迹为 $`H\to \{\mathrm{copper},\mathrm{iron}\}\to \{\mathrm{copper},\mathrm{iron}\}\to \{\mathrm{copper},\mathrm{iron}\}`$。数量多了，可辨识信息没有增加。

相应入口：`filter_evidence(H, [E1, E2])`。返回值包含初始状态，所以两条观察产生三项轨迹。每个集合均为 frozenset，显示时 demo.py 将标签排序以便稳定比较。

这解释页 100 的“再次观察”怎样可能纠错，也让一个限制变得明显：重复的观察未必排除任何新的竞争解释。

## 2. 两个失败都不能怪到交集运算上

### 2.1 真解释一开始没被保留

把 $`C_{0}`$ 改成$`\{\mathrm{copper},\mathrm{wood}\}`$，仍交给程序 $`E_{1}`$、$`E_{2}`$。

- 第一次后只剩$`\{\mathrm{copper}\}`$
- 第二次后变成$`\varnothing`$

即使后来证据忠实，也不能创造初始没有的 iron。若程序要改为提出新候选，就必须另写假设生成规则；本程序没有这一功能。

### 2.2 一条错误观察排除了真解释

保持 $`C_{0}=H`$，但把第一次证据错设成$`\{\mathrm{copper}\}`$。

- 第一次后只剩$`\{\mathrm{copper}\}`$，已经是一个看似明确的错误答案
- 再给$`\{\mathrm{iron}\}`$，结果变成$`\varnothing`$

程序没有能力判断哪个输入错了。空集也不是“没有现实真相”的证明，只表示当前候选与当前证据合不起来。规则执行正确、输出整齐，都不等于认识正确。

练习：如果只停在第一次之后，会怎样？

答案：单个候选 copper 仍会被输出，但其唯一性没有补救不忠实的证据。MODEL 的唯一识别条件同时要求保真与排除竞争者，不能只检查集合大小。

## 3. 同一个循环，两种不同问题

设 $`V=\{A,B,C\}`$，规则为 $`A\to B`$、$`B\to C`$、$`C\to A`$。这里“$`A\to B`$”在代码中写作 `Rule({"A"}, "B")`，表示若 $`A`$ 留在当前集合中，这条规则就为 $`B`$ 提供支持。

### 3.1 没有任何外部锚点

令锚点集合 $`A=\varnothing`$。为避免混淆，本段大写单个 $`A`$ 是一个判断标签，符号 $`A`$ 所表示的锚点集合则会明确称作“锚点”；二者在代码中分别是字符串 `"A"` 与 anchors 参数。

从空集合向上计算：

- 初始$`\varnothing`$
- 没有可用前提；下一次仍$`\varnothing`$
- 最小不动点 $`L=\varnothing`$，日志只保存一次$`\varnothing`$，变化次数为0

从全体向下计算：

- 初始$`\{A,B,C\}`$
- $`A`$ 获 $`C`$ 的支持、$`B`$ 获 $`A`$ 的支持、$`C`$ 获 $`B`$ 的支持
- 下一次仍$`\{A,B,C\}`$
- 最大不动点 $`G=\{A,B,C\}`$

所以“每句话都有人支持”和“能从外部给定根据推到这句话”是不同的问题。代码分别使用 `fixed_point("least")` 与 `fixed_point("greatest")`。

### 3.2 给 $`A`$ 一个外部锚点

现在 `anchors={"A"}`。

最小迭代：$`\varnothing \to \{A\}\to \{A,B\}\to \{A,B,C\}`$，随后稳定。$`A`$ 是输入，$`B`$ 有 $`A\to B`$，$`C`$ 有 $`B\to C`$；每项都能画成有限推导树。最大迭代也得到全体，所以 $`L=G`$。

结论：检测到循环本身不能证明错误。这个圈有了外部起点；而且外部锚点是否真的可靠，仍要到模型外去检查。

## 4. 撤销“根据”和禁止“判断”不相同

### 4.1 仅撤去锚点

从上一个例子撤去锚点 $`A`$，让 anchors 重新为空，其他不变。

重新从$`\varnothing`$计算得到 $`L=\varnothing`$；重新从全体计算得到 $`G=\{A,B,C\}`$。判断仍可互相支持，只是再没有外部起点。

不要从旧 $`L=\{A,B,C\}`$继续做一次更新，就声称新最小不动点仍是全体。全体的确稳定，但那是新系统的另一个不动点。`fixed_point("least")` 每次都会重新从$`\varnothing`$开始。

### 4.2 明确排除 $`B`$

现在 anchors 为空，并令 `withdrawn={"B"}`。允许集合 $`U=\{A,C\}`$。

最大迭代的完整严格变化轨迹：

1. $`\{A,C\}`$：$`C`$ 支持 $`A`$；$`B`$ 已不允许出现；没有 $`B`$ 便不能支持 $`C`$。
2. $`\{A\}`$：不能生成 $`B`$，因为 $`B`$ 被排除；也没有 $`C`$ 来支持 $`A`$。
3. $`\varnothing`$：再更新仍为空，停止。

只有 $`B`$ 是外部排除的，$`A`$、$`C`$ 是后来失去支持而消失的。这足以限制“任何互保体系都得同时删掉全部节点”的普遍说法。页 105 的政治力量、激情和习惯并不在这个静态模型里，因此不能把这个反例包装成社会改革的实验结论。

### 4.3 排除优先

若把 $`A`$ 同时放进 anchors 与 withdrawn，$`A`$ 也不会保留。本例的整个圈最终为空。这是 API 的明确冲突处理规定，不代表所有信念系统都应这样处理冲突。

## 5. 为什么有时不会全灭

设判断为$`\{A,B,C,D\}`$，规则 $`A\to B`$、$`B\to C`$、$`D\to C`$。初始锚点为$`\{A,D\}`$。

- 最小轨迹：$`\varnothing \to \{A,D\}\to \{A,B,C,D\}`$
- 只撤去锚点 $`A`$，保留锚点 $`D`$
- 新最小轨迹：$`\varnothing \to \{D\}\to \{C,D\}`$

$`A`$ 和 $`B`$ 不再有外部根据，但 $`D`$ 依然支持 $`C`$。撤回的传播受替代支持约束，并不保证整个系统消失。

对照：只保留 $`A\to B`$、$`B\to C`$ 的链，撤去唯一锚点 $`A`$ 后，最大轨迹为$`\{A,B,C\}\to \{B,C\}\to \{C\}\to \varnothing`$。链与圈的不同，不需要靠“圈总坏，链总好”来解释。

## 6. 合取前提不能随便拆成两条箭头

令唯一规则是$`\{p,q\}\to r`$，锚点只有 $`p`$。

- 第一轮得到$`\{p\}`$
- $`q`$ 未出现，规则前提不完整
- 最小结果仍只有$`\{p\}`$

再把 $`q`$ 加为锚点，才会得到$`\{p,q,r\}`$。如果误把规则换成“$`p\to r`$ 或 $`q\to r`$”，模型已被改变。作者突变检查特意注入这种错误，完整测试会将其作为行为差异检出。

再思考一个边界：唯一规则为$`\{p,q\}\to p`$，没有锚点。从$`\{p,q\}`$向下计算，第一次仅剩$`\{p\}`$，第二次全空。即使规则图可画出 $`p`$ 自环，缺少合取伙伴 $`q`$ 仍然不能互保。这是 MODEL 中“有圈不必有最大存活部分”的例子。

## 7. 第106页：学会一个词，未必确定一个意思

定义候选解释 $`H=\{\mathrm{q\_means\_warm},\mathrm{q\_means\_bright}\}`$，分别表示词 $`q`$ 的意思是“温暖”和“明亮”。

- 两个已见例子都被叫作 $`q`$，也都既温暖又明亮
- 它们各自的相容集合都等于 $`H`$
- 轨迹为 $`H\to H\to H`$，两个解释分不开

再给一个被叫作 $`q`$ 的“温暖而昏暗”的例子。按照我们预设的两个候选解释，相容集合为$`\{\mathrm{q\_means\_warm}\}`$；交集才变为单元素。

这个小例子没有自动理解语言。对象性质、词语标注与候选意义都是输入。它显示的是：如果词义解释在已有证据上无法区分，机械地增加相同类型例子并不能决定意义。

练习：如果只剩 q_means_warm，是否已证明词 $`q`$ 在现实里永远指温暖？

答案：没有。只证明当前有限候选库和当前相容判断留下这一个解释。其他可能词义、语境变化或标注错误都没有自动被排除。

## 8. 一次看懂验证证据

执行 `python3 -B run_all.py`，会保存三种解释器模式的实际输出。normal 对应 `sys.flags.optimize=0`；`-O` 对应1；`-OO` 对应2。

- test_model.py：40项作者 unittest 方法。它们检查结果、轨迹、边界输入、快照与演示。
- exhaustive.py：作者有限枚举，检查小宇宙的所有指定输入，并和定义的直接表达式对照。
- mutation_check.py：将 model.py 的一个位置改成指定错误，复制到隔离临时目录，运行同一套完整测试。失败并非一概算成功检出：只有完整执行40项、出现断言失败、没有测试错误才算行为杀死。
- 模拟导入错误、语法错误、空套件、提前退出、重复完成标记、运行时异常和真正超时，是检查测试装置的控制项。它们必须识别为各自类别，不能加入行为杀死数量。

这些是作者自己的验证；独立复核有单独署明的入口和报告。有限枚举、测试方法和突变运行属于不同统计单位，不要相加成一个夸大的“总样本数”。
