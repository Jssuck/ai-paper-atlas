# 从一个算式看“拆开以后还剩下什么”

先运行：

```bash
python demo.py
```

下面每个例子都可在 `validation/demo-output.txt` 找到实际输出。我们使用现代整数语法作教学类比；Condillac 的机器例子没有规定这种表示或操作。

## 1. 完整拆解：2 − (0 + 1)

构造树：

```python
from model import Leaf, Branch, serialize, parse, evaluate

tree = Branch("SUB", Leaf(2), Branch("ADD", Leaf(0), Leaf(1)))
prefix = serialize(tree)
restored = parse(prefix)
print(prefix)
print(restored == tree)
print(evaluate(restored))
```

结果为：

```text
(('SUB',), ('LEAF', 2), ('ADD',), ('LEAF', 0), ('LEAF', 1))
True
1
```

拆解顺序是“根、左边、右边”，但序列里不仅是数字。每个 ADD／SUB 都说明此处需要两个子式，LEAF 说明这是一个整数终点。完整序列因而同时保留部件、关系和嵌套。

从右向左重建时，以下栈以右边为栈顶：

1. 读 LEAF(1)：`[1]`
2. 读 LEAF(0)：`[1, 0]`
3. 读 ADD：先弹 0，再弹 1，得到 `[0 + 1]`
4. 读 LEAF(2)：`[0 + 1, 2]`
5. 读 SUB：先弹 2，再弹 `(0 + 1)`，得到 `[2 - (0 + 1)]`

不能交换第 5 步的两个操作数；否则得到 `(0 + 1) - 2 = -1`，已经不是原树。`restored == tree` 比较的是结构相等，未要求两者是同一个内存对象。

## 2. 只记叶子：操作丢了

`(0 + 1)` 和 `(0 - 1)` 都给出有序叶序列 `(0,1)`，也给出相同叶多重集 `(0,1)`。但输出分别是 1 与 −1。

所以“数字都在，而且次序正确”仍不足以恢复原表达式。操作也是必须保存的关系信息。

## 3. 只记数量：位置丢了

保持同一个减法操作，只交换两个叶子：

- `(0 - 1)` → −1
- `(1 - 0)` → 1

两者的叶多重集都是 `(0,1)`；区别在左右位置。排序后的多重集仍保留重复数值的个数，但不保留位置。

## 4. 记住叶次序和所有操作：括号还会丢

两个式子的叶次序都是 `(0,0,1)`，两个操作也都是 SUB：

- `((0 - 0) - 1)` → −1
- `(0 - (0 - 1))` → 1

它们的完整前缀不同：

```text
(('SUB',), ('SUB',), ('LEAF', 0), ('LEAF', 0), ('LEAF', 1))
(('SUB',), ('LEAF', 0), ('SUB',), ('LEAF', 0), ('LEAF', 1))
```

前缀里操作 token 的位置编码了括号。这里的“同样顺序”不能仅指最后排出的叶子。

## 5. 只要答案相同，究竟算不算成功？

`0` 和 `(1 - 1)` 都输出 0，但结构、部件数和叶多重集不同。

若问题是“这个式子的整数输出是多少”，二者属于同一输出等价类；若问题是“请复原我给你的表达式”，用一个替代另一个就失败了。先确定任务，才有相应的等价标准。

输出碰撞的更小示例是 `0` 与 `(0 + 0)`；有序叶或多重集碰撞的第一对是 `(0 + 0)` 与 `(0 - 0)`。这两类最小反例没有不同输出，所以教学上还需要前面那些专门改变输出的例子。

## 6. 协议错误应被拒绝

```python
parse(())
parse((("ADD",), ("LEAF", 0)))
parse((("LEAF", 0), ("LEAF", 1)))
parse((("LEAF", True),))
```

依次触发空输入、孩子不足、多余表达式、布尔值并非合法整数负载的异常。把最外层换成列表也不被自动接受。严格输入约定使“可往返”的承诺有清楚边界。

这里不是说所有有效软件都必须拒绝列表或布尔值；这是此模型为了精确定义编码域而作的选择。另一种协议可以允许转换，但需要另外定义其等价性和往返条件。

## 7. 检查全部 3477 棵小树

```bash
python enumerate_model.py
```

输出的 JSON 给出每个叶数的数量、四种表示的等价类／碰撞计数、指定排序规则下的最小结构碰撞以及输出频数。读取时注意：

- 1–4 叶是本次完整检查的有限边界，不是任意规模的抽样
- 同一整数输出的不同树不会提前合并
- 全部结构前缀应有 3477 个，Q 有 120 类，M 有 34 类，V 有 15 类
- 两个方向的编码／解码往返都在这些树上被检查
- JSON 为可读展示把元组写成列表；它不声称这些列表可直接传给严格解析器

最后运行 `python verify.py` 可重做演示、全部测试和穷举，并生成作者日志。一般往返性、计数依据、反例最小性和原文解释边界见 `MODEL.zh-CN.md`。

## 8. 阅读时值得追问

1. “每个部分都准确”之外，关系、位置、比例或因果联系是否也属于需要认识的内容？本模型只选择了其中一小部分。
2. 原文关于“按原秩序重组”的要求，针对的是对象本身、我们的观念，还是向他人表达的顺序？代码不能替历史解释作答。
3. 一个表示可以足够完成当前任务，同时不足以恢复原对象吗？上面的输出等价给出了精确的小例子。

这些问题用于回到文本，不把现代形式模型当成哲学命题的经验验证。
