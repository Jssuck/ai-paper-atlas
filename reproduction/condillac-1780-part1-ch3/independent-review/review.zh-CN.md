## 受审范围与独立性

直接受审文件为 `model.py`、`enumerate_model.py`、`demo.py`、`verify.py`、`tests/test_model.py`、`README.md`、`MODEL.zh-CN.md`、`WALKTHROUGH.zh-CN.md`，同时核对四份作者验证产物。主文第 8–10 节仅用于检查教学对象、例子和一般证明之间的对应；主文历史来源与全篇解释不属于此代码审阅的认证范围。可选图形脚本和图像也不在本次核心代码验证范围；新版 README 已把可选 PNG 依赖与标准库核心模型区分。

独立 oracle 没有调用作者的树生成、编码、求值或投影函数来产生期望结果：

1. 对每个叶数，直接选择长度 `2n−1` 的字中哪些位置是内部节点，以“尚未填入的孩子槽位”检查形状合法性。它不采用作者的左右子树叶数分拆递推。
2. 为每个合法形状分别装配所有 ADD／SUB 标签及整数叶标签。
3. 使用从左往右读取的递归参考解析器，把前缀读成整数或嵌套元组；作者实现则从右往左扫描并使用栈。
4. 在参考元组上直接计算整数值、显示字符串、叶序列和多重集，再与作者实际结果逐项比较。
5. 通过直接读取作者节点字段核对其树结构，不以作者自己的 `serialize` 结果同时充当实际值和预期值。
6. 对每个碰撞类显式遍历所有不同成员的无序对，按已声明的排序规则选择最小对，独立核对作者“先取类中前两项”的优化。

以上方法减少共用错误来源，但并不使 oracle 本身免于出错。[oracle.py](oracle.py) 公开了全部检查；没有网络、随机抽样、第三方库、训练或模型 API 调用。

### 接受语言与非法输入

用五种合法 token `ADD`、`SUB`、`LEAF(0)`、`LEAF(1)`、`LEAF(2)`，枚举长度 0–7 的所有 97,656 个序列。独立槽位判定与作者解析器完全一致：

- 合法 3,477 个，均解码为参考前向解析器给出的同一结构
- 非法 94,179 个，均以 `ValueError` 拒绝

这是对指定长度及字母表的全部序列检查，不是对任意长度输入的穷尽验证。错误 token 类型另行测试：75 个容器／token／标签／元数／负载样例，包括非法 token 处在合法表达式后面或分支内部的情形，均被拒绝。

还测试 16 个非法树对象在全部 7 个树入口上的 112 次调用，包括非节点、子类、缺字段、非法值、非法操作、坏孩子、自环和跨对象环；另有 5 个构造器拒绝案例及 10 个生成器参数拒绝案例。严格检查在两种优化模式下仍执行。

这些拒绝测试针对接口约定和可重现的绕过构造器对象，不构成针对恶意 Python 运行时代码、并发篡改或拒绝服务攻击的安全认证。

## 证明与最小性复核

`MODEL.zh-CN.md` 的反向扫描证明使用“任意已有栈”的加强归纳命题，足以说明先处理右树、再处理左树时不会破坏已有栈，也不会交换左右角色。接受输入的反向往返证明以“已处理后缀等于栈顶至栈底各完整前缀的拼接”为不变量，足以排除忽略多余表达式的情况。由往返导出的单射性及结构观察量保存结论成立。

主文的前向递归解析描述与代码的反向迭代解析是两种等价实现路线，不能把主文中的递归步骤误称为当前 `parse` 的源代码执行轨迹。主文明确补强为“任意后缀”命题，解决了读取左树时必须留下右树的边界问题。

完整有限枚举的归纳理由和 Catalan 闭式计数一致。一般证明不依赖这 3477 个用例；反过来，数学证明也不免除检查程序实现和运行资源的责任。

最小性声明的尺度已明确限定。独立遍历碰撞类中所有成员对，得到与作者相同的首对：

- 有序叶、多重集：`(0 + 0)` 与 `(0 - 0)`，最大叶数 2，总叶数 4
- 整数输出：`0` 与 `(0 + 0)`，最大叶数 2，总叶数 3
- 完整前缀：没有碰撞

在最大叶数 1 时只有不同整数叶，三个有损投影都能区分它们，因此最大叶数 2 的下界有独立理由。只改操作或左右位置的输出差异例子最少需要 2 叶；只改括号最少需要 3 叶，因为 2 叶仅有一种满二叉形状。这些结论没有被扩张成“最短编码”“所有领域中最小”或任意排序下同一个第一对。

Q 与 V、M 与 V 的不可比较性由具体反例支撑；把四种观察排成一条信息好坏链不成立。没有发现文档作出这种错误扩张。

## 示例与资源边界

演示 A–H 的独立计算输出依次为 `1, 1, −1, 1, −1, 1, 0, 0`，对应的显示、完整前缀、叶序列和多重集与保存日志一致。主文 T1–T4 的输出独立核对为 `1, −1, 0, 2`。逐步手算中的恢复顺序和括号差异正确。

另外运行了以下有限资源探查：

- 左链和右链各 5000 层、5001 叶、10001 token；解析、编码、求值、叶数和显示均通过
- 只有 13 个不同内存节点的重复共享 DAG，按出现位置展开为 4096 叶、8191 token；值和叶数正确
- 5001 位整数可构造、解析、编码、往返及求值；本环境整数转十进制字符串上限为 4300 位，`display` 因而抛出 `ValueError`
- 两棵分别构造的深树直接使用 dataclass `==`，会触发 `RecursionError`

后两项是已由 README 明确披露的运行时边界，不是对“所有数学整数和有限树必定能在有限机器上执行”的承诺违约。独立深树往返用前缀比较，避免把递归 dataclass 相等误当作无界检查。共享引用不保留身份；其展开大小可能相对于不同内存节点数呈指数增长。生成器保留全部树，显示字符串也有构造成本；这里没有测定极限、复杂度上界或性能基准。

## 定向故障注入

在内存副本中做了 8 项明确选择的故障注入，均被相应独立检查检出：编码左右交换、解析左右交换、两者同时交换、减法误作加法、多重集丢重复、接受多余表达式、接受布尔叶负载、生成器漏掉子树划分。作者原文件未改动。
