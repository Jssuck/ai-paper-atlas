# 独立代码与数学审计

审计日期：2026-10-12（UTC）。对象为本目录的有限教学程序、`MODEL.zh-CN.md`、运行说明与手算导览，以及[正文第9–13节](../../../papers/1780/condillac-logic-part2-ch3.zh-CN.md)。本审计不承担1798原典、1780版本、引文来源或一般历史论断的校勘。

## 1. 结论与已发现问题

**在明示的有限输入契约与非对抗性突变范围内通过。** 未发现候选过滤、可识别性、正Horn最小闭包、来源重放、词义对齐、规则换名或任务精确性的实现反例。普通、`-O`、`-OO`均实际执行独立检查及作者测试，不是仅检查语法或推测优化后相同。

本轮发现并处理两项问题：

1. **已修复：突变终端报告缺少结构验证。** 初次实测向`probe`提供在导入时打印`SENTINEL_RESULT={}`并退出的模块，得到`KeyError('tests')`，而非`harness_failure`。作者补上六字段集合、严格非负整数（排除`bool`）及结果计数总和检查，增加六个子进程故障控制。修复后，本审计对原始复现输入在三种模式重新执行，均得到`harness_failure / invalid_terminal_report_schema_or_counts`。
2. **保留并公开的限制：终端报告未作来源认证。** 模块可以打印一份结构完全合法的假报告（一次测试、一次失败），随后退出1；当前框架仍会把它算作`killed`，尽管测试没有运行。本审计在三个模式实测保留了这个见证。作者已在README、MODEL与导览明确排除伪造运行器报告的对抗性代码。现有十个固定源码替换没有伪造报告，因此这不推翻它们的实际检出结果；不得将本框架宣传为可安全评估恶意任意程序的隔离设施。

另核实了一个容易误读的规格差异：正文的三张预测表为A000/B001/C101，附件为true001/twin000/other111。最终说明已显式区分两套例表，附件的噪声输出与自身表项一致。正文的一般语义覆盖定理也比程序的“双射词表、相同意义域”更广，最终说明没有把较宽定理冒充已实现API。

## 2. 独立性、执行与证据

独立检查器为[`independent_check.py`](independent_check.py)，只导入核心`model.py`，**不导入作者`test_model.py`或`mutation_check.py`**。它重新构造输入与期望值；尤其用全部布尔解释的满足关系求Horn后果，而不是复写作者的前向扫描。

[`run_audit.py`](run_audit.py)负责分别执行独立检查、作者unittest和作者突变框架；后两项是对原作者证据的复跑，不算独立预言机。该运行器另调用突变`probe`验证已修复缺字段问题与仍在契约外的伪造报告见证，两者在日志中明确分开。

可在附件根目录复现：

```sh
python -B independent-review/run_audit.py
```

紧凑证据为：

- [`run-results.json`](run-results.json)：实际环境、起止UTC时间、全部九个阶段、各模式结果、有限枚举范围、故障分类、源文件运行前后SHA-256及稳定性检查
- [`commands.log`](commands.log)：九条实跑命令、退出码与耗时
- 作者的[`verification.log`](../logs/verification.log)仍保存每个突变子进程的完整stdout、stderr和退出码；独立摘要不再复制整份冗长流水

实际解释器为CPython 3.12.14，Linux环境，无安装、网络访问或第三方依赖。七个Python源文件经AST检查均无优化时消失的裸`assert`。独立检查使用显式失败异常；每个模式执行682,785次显式检查。这个数字包含同一案例上的多个性质检查，**不是682,785个独立样本，更不能将三种解释器模式相加当作新模型数量**。

两原子的完全合并不能产生“尚有另一目标原子被多推出”的见证，因此检查器另有三原子反例：规则`{p,q}→r`，仅种子`{p}`，把p、q合成x，r映成y。源闭包之像仅{x}，目标闭包却有{x,y}。没有将缺少见证的有限子域误说成一般成功。

也另查一个**错误双射仍保持结构闭包**的例子：源空前提规则产生A，正确目标规则产生X，交换A/B意义的错误词典却产生Y。错误换名规则与错误换名后的源闭包一致，同时与独立给定的正确目标规则不一致。

作者测试在每个模式仍为24个方法全部通过；十个指定行为突变均被各自哨兵检出，十个原版哨兵全部通过，十一个故障控制全部归为`harness_failure`。每个突变只运行一个指定哨兵，不能写成“每个突变都通过全套测试验证”。

## 4. 一般数学性质的单独核查

以下是对任意满足条件的有限对象的论证核查，**不以第3节穷举次数代替证明**。

### 4.1 候选集合、识别与噪声

对候选h，追加记录只向错误计数加入非负整数，故旧计数不大于新计数；固定预算b时，新合格必旧合格。此证明不需要记录真实，所以收缩本身不是认知进步的证明。类内指定真候选若错误次数不超过b，按集合定义必保留；类外真相或超预算记录均不在保证中。

无噪声、预算0时，一个错误候选被排除恰当且仅当已查位置中有一次预测与真候选不同。要使每个可能真候选都成为单例，限制到观察位置集的预测映射必须单射：单射时所有其他候选都被某个坐标排除；非单射时存在两个同签名候选同时保留。空位置集只有单候选类可识别。某一个候选被识别不推出整个类都可识别。

对同一位置序列的两个预测向量，每个彼此不同的坐标至少使其中一个与记录不同。因此二者Hamming距离不大于两个错误计数之和。若不同候选距离均大于2b，就不可能同时在预算内；再加类内真相及预算内噪声，才能从“至多一个”得到“恰为真候选”。重复位置作为多条记录逐次计数，不引入独立性或概率假设。

正文关于相同可观察预测下确定性自适应识别也成立：两个情形起始历史相同；确定性下一步选择相同，且许可位置的返回值相同，故归纳所有历史相同，算法无法同时给两个情形各自正确的不同答案。它没有声称随机算法、额外观测或扩大假设类也受相同代码接口覆盖。

### 4.2 Horn终止、最小性、闭包性质与保真

实现每次成功触发只加入一个尚无原子，故成功添加不超过宇宙中非种子原子数；每个非终止完整扫描至少成功一次，所以包括最后确认轮在内，最多`|U|-|S|+1`轮。空规则和空宇宙也终止。即时使用同轮新结论会改变轮次及来源顺序，不改变下面的最小性论证。

最终集合包含种子并对全部规则闭合。对任意另一个包含种子的闭合集T，逐次添加归纳：初态包含于T；若当前集合包含于T，触发规则的全部前提也在T，故结论在T。输出因此包含于每个这样的T，是唯一最小闭包。全宇宙本身闭合，所以“全部此类T的交”不是空族交的歧义。

扩张性来自初态；若S包含于T，T的闭包是包含S的闭合集，最小性给出种子单调；闭包已闭合，故幂等。任意持续完整扫描到无变化的规则顺序满足同一最小性证明，因此结果集合不随次序变化，证明轨迹则可能变化。

实际真集W只有同时包含种子并对规则闭合时，最小性才推出整个闭包包含于W。假种子的合法闭包不能证明事实为真；也不能反向证明所有后果必假。正文空真集、部分真结论、撤销后其他路径仍保留结论的反例均与定义相容。

### 4.3 来源核查的保证范围

检查器绑定外部给定种子，逐条核实规则身份、标准化完整前提、规则结论、前提已知及结论尚未出现。通过重放可归纳每个新原子属于真正闭包，故报告集包含于闭包。检查器又要求重放集合等于报告集，且报告集对全部规则闭合；最小性反向给出闭包包含于报告集，两者相等。

这既排除凭空引入原子、先借未来结论和遗漏未执行规则，也说明为什么仅检查终点“存在互相支持的规则”不够。它不认证种子来源，不检验现实真集，也不枚举某结论的全部证明；删除一个种子后的处理是重算，不是增量真值维护。

### 4.4 一般语义覆盖、受限词表及规则换名

正文一般定理允许词典多对一：总保义转换存在当且仅当源词典意义像包含于目标意义像。必要性由每个翻译结果的意义必须在目标像内；充分性是在有限源符号上，为每个源符号选择一个同意义目标符号。空源域有唯一空函数，空目标域也被覆盖条件正确处理。这个证明未要求双射；目标同义词还会使选择不唯一。

程序`Vocabulary`采用更窄条件：每个意义恰有一个词码，两侧意义集相同。于是唯一保义字典必为“源词解码后按目标词编码”；左复合目标编码即可从保义等式推出唯一性。`inverse_dictionary`只检查到实际像的逆，不包含外部目标域的满射保证。即使双向可逆，词码对调仍可改变意义。

双射换名保持并反映前提集合包含关系，所以逐轮同步闭包互为像；结合最小闭包唯一性，同样适用于异步扫描实现。规则本身也按错误双射转换时，这个纯结构等式仍成立，因为证明没有使用词典意义。把它称为语义正确必须另加意义对齐与独立目标规则条件。非单射只保持向前包含，可能制造额外触发；正文与附件的反例均正确。单射到实际像已经足够，不必把双射条件误读为所有特殊实例的必要条件。

### 4.5 任务因子分解与分区

标签L能确定任务q，当且仅当同标签的每两个世界答案一致。若q通过标签后的函数g得到，相同标签必同答案；反之，在每个已使用标签上任选一个世界定义答案，同纤维一致性使g与代表选择无关。这也是标签分区细化答案分区。

若新标签分区细化旧标签分区，同新标签推出同旧标签，再推出同答案，所以精确性保留。块数更大本身不保证细化；四世界两块/三块例子确实给出反例。正文多任务形式是逐个任务同时满足条件；程序`task_exact`单次只检查一项任务，没有假称自动接收任意任务集合。

## 5. API与工程边界

- 输入中的位置、候选名、原子名、规则名、词码与任务答案须为非空字符串；错误预算严格为非负`int`，`bool`被拒。不是任意Python对象均能作为意义或答案。
- 观察是有限序列，重复或相互冲突合法；未知位置非法，而且全部记录先验证，不因较早矛盾跳过后面的坏输入。程序未预列结果域，所以未被候选预测的新结果仍是合法观察。
- 候选位置和候选类非空；空Horn宇宙、空规则、空前提、空种子和空词表被分别处理。规则前提重复按集合合并，不是另一个多重计数语义。
- 构造器复制输入容器；已构造模型不会因调用方随后修改原列表而变化。`ClosureResult`与`Derivation`是证书记录，不应仅凭构造成功就视为有效；须交给`verify_trace`。
- `aligned_dictionary`与`translation_preserves`预期收到已构造的`Vocabulary`实例，并不为任意错误对象统一包装`ValueError`。本审计没有把“44个坏输入正确拒绝”升级为“所有Python级滥用都被防御”。无限迭代器、恶意自定义方法、绕过冻结对象、并发输入修改与运行环境故障均在原契约外。
- 复杂度分析与代码相符：候选查询包括位置元组成员检查；Horn扫描包括重复全规则扫描与来源前提排序。有限枚举不是可扩展性能基准，也没有真实语言数据、概率学习或心理实验。
- 日志是带时间与源码哈希的运行快照。`run_all.py`遇到外部中断或未处理子进程超时，并不保证刷新旧日志；不能把残留日志当作之后任意新代码的健康证明。应核对本次命令是否退出0及哈希是否对应待发布源文件。

## 6. 未声称覆盖的事项

没有枚举三原子的全部`2^24`个规则系统，没有对所有Python输入对象穷举，没有检验任何规模下的性能，没有把24个测试方法当作24条一般数学证明，也没有对恶意模块作隔离安全承诺。

本审计与作者检查共同支持的是：这些指定有限算法在已说明的环境和输入范围内符合规格；数学一般结论由第4节的定义与证明支撑。语言的真实起源、经验必然纠错、所有思维必须依靠语言、语言接触的历史后果或孔狄亚克的思想首创权，均不由这些程序及测试成立。
