# 手算导览：三种“检查通过”为什么不是同一种成功

这是为1798底本《逻辑学》第二部第三章118–124页新写的教学附件。下列例子、数字和代码均非孔狄亚克原例，不构成心理学实验。读原文时要分别问：经验排除了什么？推导依据了什么？翻译保留了什么？

[模型与一般证明](MODEL.zh-CN.md)说明条件；本页把固定例子算完。运行`python -B demo.py`会输出同一组数据，完整实测保存为[results.json](logs/results.json)。集合在JSON中排序以保证结果可比，排序本身不表示重要性或可信度。

## 1. 三个假设，只看两个位置还不够

观察位置为x、y、z。候选的预测表是：

| 候选名称 | x | y | z |
|---|---:|---:|---:|
| true | 0 | 0 | 1 |
| twin | 0 | 0 | 0 |
| other | 1 | 1 | 1 |

这张附件例表与正文A000/B001/C101的例表不同，以下噪声输出仅对应本表。名称true只是示例中指定的真实候选，不是程序有判断真相的额外能力。

1. 没有观察，三个候选都符合。
2. 观察x=0，other被排除，true和twin保留。
3. 再观察y=0，两者都仍符合，候选没有减少。
4. 最后观察z=1，twin被排除，只剩true。

所以候选数为3→2→2→1。“有新数据”不等于“有新区分”。只看x、y能够检出other这一错误候选，却不能区分true与twin。位置集合{x,z}则能区分全部三个候选，签名分别为(0,1)、(0,0)、(1,1)。

相关调用：

```python
space.candidates([('x', '0'), ('y', '0')])  # {'true', 'twin'}
space.distinguishes(('x', 'y'))             # False
space.distinguishes(('x', 'z'))             # True
```

Python实际返回冻结集合，注释用普通集合显示内容。不要从两行例子归纳出任何新观察都必有区分力；一般单调性及可识别充要条件见MODEL命题1、4。

### 如果第一条记录错了

现在记录为(x=1,y=0,z=1)。三个候选与记录不一致次数分别是：true为1，twin为2，other为1。精确过滤把三个全删掉；错误预算设为1时，留下true和other。

预算救回了真实候选，也同时留下另一个候选。它没有告诉我们哪条记录错了，更没有给出各候选的概率。如果只看错误的第一条x=1，甚至会唯一剩下other。**唯一、非空、单调缩小，都不能替代类内真相与可靠观测条件。**

另一个独立问题是候选类本身漏掉了真相。若真实机制预测(0,1)，但唯一候选预测(0,0)，观察第一项0仍会留下这个唯一错误候选。只有观察第二项1后才发现不相容。空集是检查的警报，不能自行判明误差来源。

## 2. 推导每一步都合法，还会错吗

用三个玩具原子rain、wet、slip和两条规则：

- rain推出wet
- wet推出slip

这些是抽象规则，不是声称下雨一定造成滑倒。程序故意把wet→slip排在rain→wet之前，检验实现是否会继续扫描到固定点。

从种子{rain}开始：

1. 第一轮看wet→slip，wet还不在集合中，不能触发。
2. 同一轮看到rain→wet，加入wet，并记下规则rain_to_wet、前提rain、结论wet。
3. 第二轮wet→slip得以触发，加入slip。
4. 第三轮没有任何新原子，终止。

闭包为{rain,wet,slip}。来源列表顺序是先wet，后slip。对照`results.json`的horn.trace，可以把每个结论追溯到先前已有的原子。

再把完整闭包当种子重新运行，原子集合不变，新增来源列表长度为0。这是幂等性，不是第二次运行重新验证了现实。

### 一个完整的假事实链

设实际三个原子全部为假，即真原子集合为空。两条正Horn蕴含在这个真值赋值下都满足：没有真前提却假结论的违反情形。但如果我们仍错误地把rain当作种子，前述三个原子照样全部推出。

来源检查会返回True，因为它检查“从给定种子按给定规则是否得到这一闭包”。它不会替种子做观测，也不会从规则名称读懂天气。这个区别对应本章122页一个有力问题：从错误起点出发，后面愈加连贯，并不自动使判断更可靠。

### 还要避免两个程序级混淆

第一，合取前提必须全部具备。规则{a,b}→c遇到种子{a}时不能触发；把“全部”错误写成“至少一个”，会无依据地产生c。

第二，无种子的循环不能自行启动。规则a→b、b→a与空种子得到空闭包；有种子a时才得到{a,b}。规则空前提→a则另当别论，因为它被我们明文规定为无条件规则。

穷举测试对所有三原子、最多两条规则的系统和所有种子，比较程序闭包与“全部含种子闭合集之交”。这个有限对照验证实现；任意有限规模的结论仍依赖MODEL命题5、6。

## 3. 翻过去再翻回来完全一致，够了吗

先约定共同意义，不让字形决定含义：

| 意义 | 词表A | 词表B |
|---|---|---|
| 雨 | rain | lluvia |
| 湿 | wet | mojado |
| 干 | dry | seco |

正确字典把rain映为lluvia、wet映为mojado、dry映为seco。源规则rain→wet对应目标规则lluvia→mojado。从雨种子出发，两边都得到“雨、湿”。这就是语言接触可以完全保持本模型意义的成功例子。

现在改用错误字典：rain→lluvia、wet→seco、dry→mojado。它依然一对一，也覆盖了全部目标词，所以可以精确反转。

- wet翻成seco
- seco按这张字典的逆再翻回wet
- 往返无字形损失，但目标语言把seco解作“干”

所以“往返原样”与“目标读者理解相同意义”是两个不同检验。代码的`inverse_dictionary`只处理前者的函数条件；`translation_preserves`专门检查后者。

### 两种闭包检查也要分开

源系统从rain推出{rain,wet}。

1. 正确翻译源闭包，得{lluvia,mojado}，与目标真正规则推出的结果一致。
2. 错误翻译源闭包，得{lluvia,seco}，与目标真正规则的{lluvia,mojado}不一致。
3. 如果连目标规则也一起错译为lluvia→seco，则目标从lluvia也推出{lluvia,seco}。这时形式计算又一致了，但词义没有修复。

这一点最容易在测试中漏掉：如果“期望输出”也由同一张错误字典生成，形式一致性可能掩盖共同错误。应明确哪个核查器依据共享意义，哪个只依据符号结构。MODEL第4节把两个交换图分别写成等式，并证明需要什么条件。

这里没有声称多语言交流本身使人误解。成功例已经说明正确对齐可行；错误例把失败定位到字典和规则的具体不一致。

## 4. 两个词比三个词还精确？要先问任务

世界只有w1、w2、w3、w4。当前任务是回答safe或unsafe，分别为(safe,safe,unsafe,unsafe)。比较两种标签方案：

| 世界 | 任务答案 | 两标签方案 | 三标签方案 |
|---|---|---|---|
| w1 | safe | A | X |
| w2 | safe | A | Y |
| w3 | unsafe | B | X |
| w4 | unsafe | B | Z |

两标签方案中，A总能答safe，B总能答unsafe，故任务精确。三标签方案的X可能是safe，也可能是unsafe，因此不精确。多出来的Y、Z并未补救X的混淆。

关键不是两个永远胜过三个。如果三标签方案真正细分原有两块，而不跨任务混合，就能保持精确。例如(A1,A2,B,B)仍精确。我们比较的是分区是否保留任务所需的区别，而不只是块数。

换任务后结论可能改变。本例支持120页“广度不是精确性的充分条件”的有限类比，不能当作少词语言天然优越的证据。

## 5. 自己检查结果，不只看“通过”

从本目录运行：

```sh
python -B demo.py
python -B -m unittest -v test_model
python -O -B -m unittest -v test_model
python -OO -B -m unittest -v test_model
python -B run_all.py
```

前三种测试模式检查显式输入异常与unittest断言在优化后仍有效。最后一条另跑每模式10个人工突变、10个对应原版基线和11个故障分类控制，并刷新三个作者日志文件。

一个突变只改一处行为，例如让“任何一个前提”替代“全部前提”，或让错误词义映射也通过语义检查。每个突变只跑它指定的一个哨兵测试，故不能把10/10读作全套测试对每个突变的覆盖率。记录中的分类含义是：

- killed：哨兵完整执行，发生预期形式的测试断言失败
- survived：哨兵完整执行且通过，说明这项检查没有抓到该突变
- harness_failure：语法错误、导入失败、提前退出、真实超时、测试运行异常、非法JSON或不合法的结构/计数报告，不能作为行为检出

此分类只适用于列明的不伪造报告的十个实现突变；同进程恶意代码若伪造一份结构合法的终止报告仍可能误导框架，不能把它当安全隔离或输出认证。

本次作者实测每模式10个突变全被指定哨兵检出，原版基线全通过，十一种故障都归入harness_failure。实验特意检查最后一种区别，避免把“程序没跑成”包装成“测试抓到了算法错误”。完整stdout、stderr和退出码保存在[verification.log](logs/verification.log)。

## 6. 做完例子后应保留的四条结论

1. 观察能排除不相容假设；得到真相还要问真相是否在类内、观察是否可靠、候选能否区分。
2. 正确执行推导规则能保留规则后果；它不会自动修正虚假起点。来源完整与事实真实是不同要求。
3. 精确逆映射和闭包形式交换都可能与词义错误并存；共同语义对齐需要单独检查。
4. 词更多不是任务精确性的充分条件；真正需要的是任务相关的区别未被合并。

这些是现代模型在明示条件下的结论。回到历史文本时，它们帮助拆清问题，不替代对孔狄亚克强历史主张的证据要求。
