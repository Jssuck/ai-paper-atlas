# Curry 1930 第一部分：组合子归约与有限公理等式证书

本包是对 H. B. Curry《Grundlagen der kombinatorischen Logik. Teil I》（1930，*American Journal of Mathematics* 52(3)，509–536）的有界、可运行复现。目标是让读者实际检查定义、归约步骤、公理的作用，以及若干需要额外公理的等式证明。

**核心边界：四条定向归约规则 ≠ 原文整个等式理论。**

- `curry.py` 的 reducer 只有 B/C/W/K 四条规则；I 是 WK 的语法缩写。
- 单独的证书核接纳原文的 16 条有限组合子公理，以及原文 I.D 已证明的等式性质。它核验具体证明证书，不是等式判定器。
- 没有完整实现 Q/Π/P/Λ 断言演算，也没有在程序中从其最底层规则重建 I.D 的全部推导。等式性质在此作为已证明的可用规则导入。
- 不声称证明原理论的一致性、完备性、合流性或一般终止性；不把第一部分视为全篇完成；不实现第二部分的组合表示、正规／适当组合子等总定理。

## 快速运行

要求 Python 3.10+；发布时实际测试 Python 3.12.14。**无第三方依赖，不需要安装 Jupyter。** 在本目录执行：

```sh
python -B -m unittest -v test_curry
python -B run_demo.py
python -B review_independent.py
python -B execute_notebook.py --check
```

一键重新生成全部执行记录、notebook 输出和文件摘要：`python -B run_validation.py`。

- `-B` 避免生成 `__pycache__`。
- `tutorial.ipynb` 已保存全部 10 个代码格的真实执行输出。
- Notebook 输出是 `execute_notebook.py` 用标准库 `exec`、共享命名空间、显式捕获 stdout/stderr 产生的，**没有启动 Jupyter kernel**。元数据记录了该事实、Python 版本及执行时间。
- `--check` 从头重跑并比较保存的输出，不改写 notebook。若更换 Python 小版本，第一格显示的版本号会变化；这不是数学结果变化。检查后可去掉 `--check` 刷新输出。
- 此脚本只用于随包的可信 notebook，不提供安全沙盒，不模拟 IPython 魔法、富显示或异步格；它做基本结构检查，不宣称通过官方完整 nbformat schema 校验。也可在 Jupyter 中打开并自行 Run All。

## 1. 精确到程序的原文对应

| 原文位置 | 对应实现 | 不能据此声称的结果 |
|---|---|---|
| I.C.2–4，pp.519–521 | 不可变 `Atom` / `App`；左结合应用；I≡WK | 应用语法并不等于全部逻辑解释 |
| I.C.6，p.522 | Bxyz→x(yz)、Cxyz→xzy、Wxy→xyy、Kxy→x | 箭头方向及求值策略是本复现的选择 |
| I.D，pp.522–525 | 反身、对称、传递、应用同余；Ix=x 的 W/K 证书 | 没有从 Q/Π 系统完整机械重演 I.D |
| II.B.1，pp.529–531 | B₀≡I，B₁≡B，Bₙ₊₁≡BBBₙ（n≥1） | n=0…6 的实验不是所有 n 的归纳证明 |
| II.B.3，pp.531–532 | C₁≡C、Cₙ₊₁≡BCₙ；W/K 同式 | 没有实现第二部分的序列分类理论 |
| II.B.4，pp.532–534 | X·Y≡BXY；乘积序列按定义左结合 | 乘积结合律不能作为语法定义偷用 |
| I.C.5、II.B.5，pp.521、534–535 | 16 条有限公理；BW 采用后文明确形式 | 饱和作用检查不证明未加参数的原公理 |

解析器允许紧邻大写字母：`BBC` 就是 `B B C`；小写标识符可以多字符，应用间需留空格。`B2` 是原子名称，不是序列缩写；用 `sequence("B", 2)` 获取 B₂。打印器显式展开 I 为 `W K`，便于核查树形。

“弱归约”若用于描述本包，指没有增加 η／外延性规则的四规则组合子归约；程序会递归进入应用两侧，并非只算到弱头正规形。策略是最左最外层；燃料计数的是收缩次数，不是 AST 访问次数。

## 2. 可运行的正例与边界

### I 的定义确实产生恒等作用

```text
I x ≡ W K x → K x x → x
```

程序没有 I 的第五条归约规则。这两步分别由 W、K 证书核验。

### 索引组合子确实改变指定位置

```text
B₃ f g x1 x2 x3 →* f (g x1 x2 x3)
C₃ x0 x1 x2 x3 x4 →* x0 x1 x2 x4 x3
W₃ x0 x1 x2 x3 →* x0 x1 x2 x3 x3
K₃ x0 x1 x2 x3 →* x0 x1 x2
```

测试覆盖 B 的 n=0…6、C/W/K 的 n=1…6，以及若干 B 序列的双索引提升实例。B₁≡B 是定义；B₁=BBB₀ 则是 p.531 的等式定理，二者没有混写。

### BI 与 I：作用相同，裸项归约结果仍不同

```text
normal(B I) = B (W K)
normal(I)   = W K
B I x y →* x y
I x y   →* x y
```

两个裸项都是四规则正规形。本程序不会由追加参数后的相同输出自动推断 BI=I。等式证书必须显式引用 Ax.I₂。p.531 的 CBI=I、BxI=x 证书分别使用 Ax.I₁、Ax.I₂，再加四规则及同余；它们不是隐藏的 reducer 扩展。

### 复合乘积结合律

```text
normal((x·y)·z) = B (B x y) z
normal(x·(y·z)) = B x (B y z)
```

加上 u 后两边都得到 `x (y (z u))`。若要证明未加 u 的等式，程序按 pp.532–533 的路线，用 Ax.B 的应用实例建立 B(x·y)=Bx·By，再以有限证书推出结合律。此证书有 47 个树节点，使用的有限公理集合只有 `{B}`；没有外延性／η 规则。

这些通用证明先针对新鲜符号建成，再结构性地同时替换为任意项；因此即使 x、y、z 都是 WWW，等式证书仍能有限检查，完全不求值这些发散实参。

### 非终止与燃料不是同一回事

```text
W W W → W W W
K x (W W W) → x
```

WWW 的唯一红项就是它本身，所以这个具体项没有四规则正规形。重复环检测返回 `cycle`，不会错误标成正规形；关闭环检测后用尽预算返回 `fuel_exhausted`。

一般项上的策略重复环，只说明该策略重复；有限燃料用尽只是未决，不能据此宣称不存在正规形。程序也不是针对深树、大规模展开的高性能求值器：递归深度、内存、重复环历史与证明树大小均有限制。

## 3. 十六条公理的检查究竟检查了什么？

对每个闭项等式附加足量的新鲜符号参数，使两边归约为**同一棵只含变量的树**。这比仅抽几个整数代入更清楚地暴露组合结构，但依然只建立这些已加参数的等式，不能反向消去参数来证明裸公理。

每次归约轨迹都转成证书，由不调用 reducer 的匹配函数的核再次检查。单元测试另用独立的 Python 柯里化函数解释 B/C/W/K，再检查同样的变量树；并把 pp.534–535 的乘积式单独结构录入，逐侧核对展开式。

## 4. Ax.(BW) 的原文差异，绝不静默修正

在 p.521 高分辨率扫描中，字面读法似为：

```text
BBW = B(B(B(B(BW)W)(BC))B(BB))B
```

依左结合约定，附加 x0、x1、x2 后，四规则归约得到：

```text
左：x0 (x1 x2) (x1 x2)
右：x0 (x1 (B x0)) (x1 x2)
```

本实现的 BW 公理采用 p.534 的明确乘积式，多个点号按 p.534 Def.3 左结合：

```text
B₁·W₁ = W₂·W₁·C₂·(B₂ B)·B
```

展开并用 B 规则化简局部 B₂B 后，右侧为：

```text
B(B(B(B(BW)W)(BC))(B(BB)))B
```

这个版本得到预期的 `x0 (x1 x2) (x1 x2)`。代码在 `BW_P521_LITERAL` 保存前一个字面读法，单元测试保留其差异；它没有进入证书核的可信公理集。

这是**扫描字面读法与后文重述之间的可复现差异**，可提示排印问题；不是已确认的官方勘误，也没有假装 p.521 原式原样通过。16 条公理的“全部通过”一律指这里声明的 p.534 BW 版本。

## 5. 验证范围与可信边界

实际执行结果见 `logs/` 与 `results.json`：

- 34 个 unittest 通过；包括 250 个固定种子随机项的整段有界轨迹核验
- 16 条有限公理在所列符号参数数量下通过作用检查
- 独立审查：1,500 个深度不超过 4 的随机项；588 个产生的步骤被独立嵌套模式红项枚举器识别，并通过证书核
- 拒绝伪造归约、错接的传递链、不存在的公理以及臆造的 η／外延性规则
- 通用证明构造器通过 WWW 发散实参检查
- 10 个 notebook 代码格由标准库执行，随后重跑输出一致

可信基础包括手工录入的原文公式（BW 版本选择已披露）、Python 实现、AST 表示、证书核的各规则以及 I.D 导入的等式性质。证书核本身也只是经过审查和测试的程序，没有在另一个证明助手中形式验证。随机样本与有限回归无法排除所有实现缺陷。
