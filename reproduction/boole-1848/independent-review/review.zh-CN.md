# Boole 1848 教学代码独立审查

## 结论与范围

本轮逐一阅读 `boole_model.py`、`test_model.py`、`demo.py`、`run_checks.py` 以及 README 和 WALKTHROUGH，重新运行作者测试，并另写独立检查程序。对文档明确限定的有限整数集合、精确有理指标语义，**未发现阻断性错误**。作者22个测试方法在普通、`-O`、`-OO` 三模式重新通过；独立检查也在三模式通过且输出JSON字节一致。

这是独立代码与数学语义审查，不是证明助手认证、软件无缺陷保证、全部历史三段论规则复现或心理学实验。不存在据有限检查推定全部一般定理成立的结论。

## 已核实的关键点

1. 代码保留普通有理数加法而非幂等逻辑或。`equation_holds` 检查实际占据的成员类型是否落入禁止类型，不把不同对象的正负残差求和抵消。
2. 展开式对每个0/1成员点激活唯一构成项。端点判准不计算0/0，正确区分自由、唯一选择和无解。
3. `solve_last_class` 按**对象**选择输出，而不是按整个成员类型选统一开关，因此同一自由区域内可选任意子集。四对象船舶模型与独立集合式全解比较一致。
4. 固定V的补类参数化保留Y⊆V侧条件；不兼容时抛错，而非悄悄产生伪解。
5. 特称见证测试明确指出裸选择等式总能以空选择满足。非空公共部分才与交集非空等价；这属于明确的现代存在政策，不把它倒署给原文。
6. Ex.3 消元单式的反例真实成立。保留X⊆V、Z⊆V′后，与“存在Y满足原两式”在独立三对象全枚举中一致。一般理由是按每个对象的四种V/V′成员状态构造Y，不能仅以枚举结果代替这项证明。
7. 主要检查使用 `unittest` 方法；独立脚本使用显式条件与异常，而非可能被优化移除的裸 `assert`。三种优化模式确实执行，不是复制一份结果。
8. 作者运行清单内4个源码SHA-256、6份运行日志SHA-256及零退出码全部重新匹配；三份演示JSON字节一致。审查重跑没有覆盖作者冻结的 `logs/`。

## 独立输入范围与计数

每一种优化模式实际执行：

- 四变量成分指示比较256次。
- 取值字母表 {−2/3, −1, 0, 1/5, 2} 的全部625个二元值表：展开比较2500次；二对象论域上全部输出集合对照2500次。
- 取值0/1的全部256个三元残差表：二对象论域、全部固定X/Y组合，共4096次完整输出解集比较。此处“全部”只针对明示的有限值表输入族。
- 四对象船舶模型：256组X/Y的解集比较、256组自由子区域参数化比较及4096次方程直接集合语义比较。
- 四对象固定选择V/Y：81个兼容组合的全部参数解比较，175个不兼容组合的拒绝与空解集检查。
- 三对象Ex.3投影：4096组V/V′/X/Z，与独立枚举Y比较。
- 三对象特称：64组X/Y分别检查裸等式可满足、非空公共选择与交集非空等价。
- 3种临时故障注入被检出：把自由端点缩为仅0、反转禁止类型、反转构成项指示。每次均恢复原函数，未修改作者源码。故障注入覆盖并不等于穷尽所有缺陷。

这些计数由独立脚本实际累加输出，不是用范围公式代替执行。作者测试覆盖计数另见其README和原日志，二者不合并成“样本总数”来夸大结论。
