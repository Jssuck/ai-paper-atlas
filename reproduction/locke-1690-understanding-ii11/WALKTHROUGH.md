# 从洛克 II.XI 到三个有限模型：中文手算走查

这份附件配合[正文](../../papers/1690/locke-understanding-ii11.zh-CN.md)第3、4、6节。哲学来源是洛克《人类理解论》第二卷第十一章；下面的映射、计数向量、版本空间与程序都是现代教学重构。没有复现人的心灵，也没有进行动物或医疗实验。

阅读时分清三件事：原书提出什么问题，数学在什么假设下证明什么，以及代码在多大的有限输入上确实通过检查。一般证明见[复现说明](README.md)；真实运行记录见 `run_summary.json`、`environment.json` 与 `logs/`。这里给出可以不用运行程序也能核对的例子。

## 一 先把对象、表示和问题分开

取三张卡：

- `white_1`：白色，编号为1，对应正文的甲
- `white_2`：白色，编号为2，对应正文的乙
- `blue_3`：蓝色，编号为3，对应正文的丙

颜色表示把前两张卡送到 `white`，把第三张送到 `blue`。这已经合并了甲乙的区别，但是否妨碍回答问题，要看问题是什么。

### 1.1 一元问题“它是白色吗”

在白色这一组里，甲和乙都回答真；蓝色组的丙回答假。所以只看到颜色标签，仍能正确回答。代码 `descend_unary` 返回：`white` 对应真，`blue` 对应假。

这里检查的是每一组内部是否恒定。不要因为这个一元问题能够回答，就推断任何二元比较都能回答。

### 1.2 二元问题“两张卡同色吗”

有四种有向标签对。白对白为真，白对蓝为假，蓝对白为假，蓝对蓝为真。同一个标签对下的所有原对象对都给同一值，所以可以形成一张精确抽象关系表。

代码 `descend_relation` 返回成功，`same_color_descends` 为真。虽然这个具体关系对称，程序并没有预先把一对与其反向合并；测试中另有不对称关系，防止实现偷换定义。

### 1.3 二元问题“第一张编号更小吗”

白对白这一格包含四对原对象：

- 甲对甲：$`1\lt1`$ 为假
- 甲对乙：$`1\lt2`$ 为真
- 乙对甲：$`2\lt1`$ 为假
- 乙对乙：$`2\lt2`$ 为假

只输入白白，不可能同时恢复这一真三假的结果。因此该关系不能精确下降到颜色表示。

程序按输入次序保存每种真值遇到的第一对，因而返回真见证 `white_1` 对 `white_2`，假见证 `white_1` 对 `white_1`。正文用甲乙与乙甲说明同一障碍；乙甲也是有效假见证，见证并不唯一。重要的是：两对必须属于同一个纤维的笛卡尔积，而且原关系真值确实相反。

`strict_rank_order_descends` 因此为假，`strict_rank_order_conflicts` 保存这些对象名，而不是只报告一个无法检查的“失败”。程序不会随意选一个代表后强行填完表。

### 1.4 为什么检查的是笛卡尔积

设对象表示为 $`r`$，标签 $`a`$ 的纤维为 $`F_a`$。标签对 $`(a,b)`$ 隐藏的不是一个对象，而是所有可能原对象对 $`F_a\times F_b`$。要使同一标签对有唯一答案，这个矩形里的每一个原关系值都必须相同。

一般证明有两个方向：如果标签规则存在，同一输入只能有一个输出，所以矩形恒定；如果每个矩形都恒定，就把它的唯一值定义成标签规则，因此规则存在。有限程序逐矩形查值，只是实现这条已经证明的规格。

空对象域也明确处理：实际像集为空，返回唯一的空字典 `{}`，这是成功；失败使用 `None`。对从未出现的外部标签，原对象根本没有提供约束，因此这里不冒称整个外部标签域的规则唯一。

## 二 为什么一打不能用普通集合表示

用一个原子 `unit` 代表一种单位。计数为1时是一个单位，计数为12时是一打。普通集合会去掉重复，因此十二次相同的 `unit` 仍只得到一个元素。

现代模型把组合表示为非负整数向量。若原子表只有 `unit`，一个单位是 $`(1)`$，一打是 $`(12)`$。把5个与7个合起来，逐坐标相加：

```math
5+7=12.
```

`results.json` 中，`dozen_total` 为12，`ordinary_set_cardinality` 为1。`duplicate_entries_add` 把同一原子的5与7两条输入相加，得到12，而不是用后一条覆盖前一条。

### 2.1 空、零、重复与负数分别怎样处理

- 空原子表允许：只有一个空计数向量，总数为0
- 原子表里的重复名字不允许，否则坐标身份不明确
- 输入条目重复同一原子允许，次数相加
- 零次数允许，但不会出现在非零支持集或精简输出里
- 负数、浮点数和布尔值不允许作为次数
- 未登记原子即使次数为0也拒绝，避免拼写错误被默默吞掉
- 乘以0得到同一原子表上的零向量

零向量的原子表仍有意义。原子表不同的两个向量不能直接相加；需先明确怎样重命名或投影。输入原子表的排列次序会被规范化，不影响同一组坐标的相等判断。

### 2.2 先组合再重命名 为什么等于先重命名再组合

把 `red` 与 `blue` 都改名为 `token`。正文的两个组合是红2蓝1，以及红1蓝2。它们本来不同，改名后都变成单位3。模型的实现把目标名字相同的次数累加。

再取红1蓝0与红1蓝1。先相加得到红2蓝1，再改名得到单位3。先各自改名得到单位1与单位2，相加仍是单位3。

这不是只对该例成立。每个目标坐标都把同一批源坐标相加；有限求和对加法分配，因此所有输入都满足：

```math
h_*(m+n)=h_*m+h_*n.
```

这里的下标星号是推送计数的现代记号，不是原书符号。同态性质说明组合操作相容；红蓝合并的反例说明相容并不等于可逆。若重命名是单射，每个源原子有单独的目标位置，次数就能恢复；若合并了两个源原子，两个不同单位向量立即构成不可逆的见证。

### 2.3 只保留红色 与重命名不是同一步

`project` 的操作是丢掉未保留坐标。红2蓝1与红2蓝7投影到红色后都得到红2。它依旧保持加法，却会减少总数；把所有原子改名为一个目标则保持总数，但丢掉来源类别。

因此不要把“投影”和“重命名”统称为一个没有规格的“抽象”。两者保留和丢失的东西不同。计数模型还忽略先后、排列和角色；它只为正文的一打及加法组合问题服务。

## 三 两个已见样本 为什么留下四张策略表

刺激域固定为四张卡：`white_circle`、`white_square`、`blue_circle`、`blue_square`。输出用字符串 `"0"` 和 `"1"` 编码。这里的字符串只为让接口采用明确的动作名字，不增加数学内容。

观察两项：白圆输出1，蓝圆输出0。白方与蓝方尚未观察。

### 3.1 规则与查表都能解释观察

候选 `color_rule` 按颜色回答：白色为1，蓝色为0。它对白方预测1。

候选 `observed_lookup_default_0` 记住白圆为1、蓝圆为0，对其余输入一律回答0。它对白方预测0。

两者在已见两项上完全相同，却在未见白方上不同。不能只拿已见两项的正确表现来区分这两个候选。也不能把一个没有出现在有限记录中的表现，直接升级成关于所有情境或内部能力的否定。

### 3.2 手算全部相容表

四个位置各可填0或1，共有 $`2^4=16`$ 张完整表。观测固定白圆和蓝圆两个位置，另外两个位置自由。按“白方、蓝方”的次序，相容的自由值为：

1. $`(0,0)`$
2. $`(0,1)`$
3. $`(1,0)`$
4. $`(1,1)`$

所以 `admissible_total_tables` 为16，`survivors` 为4。注意上述两个具名候选只是四张中的两张；不能把“举了两个替代解释”错报为“全部候选恰好两个”。

在白方上，一些相容表输出0，一些输出1；`held_out_possible_actions` 为 `['0', '1']`，`held_out_status` 为 `underdetermined`。对已见白圆，则所有相容表输出1。

### 3.3 一致预测为什么要说候选范围

如果事先只允许 `color_rule`，白方的预测立刻变为1，状态变为 `unanimous`。数据并没有增加；改变的是允许的候选范围。因此保证依赖“真实策略属于所列候选类”这一假设。

如果再观察白方输出1，在两个具名候选中只剩 `color_rule`。输出 `two_candidate_survivors_after_positive_holdout` 记录的正是这个两候选问题。若仍允许全部16张表，则还有两个候选，因为蓝方尚未观察。两种候选范围不能混为同一个实验结果。

即便四张卡全部观察完，确定的也只是这个有限域上的行为表。不同程序可以给出同一张表；同一完整行为不等于同一内部机制。测试中把两个不同名字的相同完整表同时保留下来，明确覆盖这个边界。

此处保留的是两个候选描述，不是两个不同外延函数。前面的16张与四张计数，按不重复的完整输入输出表计；`enumerate_policies` 也只生成这些不同表。重复描述不改变可能预测集合，不能用它增加全函数计数。

### 3.4 空版本空间不是“所有答案都对”

如果仅允许一个候选，却观察到它无法解释的输出，相容候选数可以为0。程序此时报告 `empty_version_space`，可能动作集合为空，`unanimous` 返回 `None`。它不会借空集上的全称真，为任何具体答案背书。

同一刺激出现两个矛盾输出则直接拒绝输入，因为当前模型明说它是确定性的。相同记录重复输入允许，但不增加约束。处理噪声、概率策略或错误观测需要另一个模型，这份附件没有实现这些扩展。

如果在数学上把矛盾记录直接放入“满足每条记录”的约束，没有确定性函数能够满足它们，所得版本空间为空。接口作了更严格的入口选择：先拒绝这种记录；只有记录合法但与候选类不相容时，才正常返回上述空空间状态。两者不要混读成同一条程序执行路径。

## 四 怎样核对实跑 而不把有限枚举当一般证明

在本目录执行：

```bash
python3 -B run_checks.py
```

脚本实际运行普通、`-O`、`-OO` 三种解释器模式。每种模式都先记录解释器信息，再运行同一组测试与例子。命令、退出码、时间、日志路径和例子哈希记录在 `run_summary.json`。最终成功要求所有命令退出码为0、三种优化模式实测无误、测试数量确实从日志读到，而且三份例子输出逐字节一致。

`-O` 会去掉普通 `assert` 语句；实现与有限检查使用显式异常，单元测试使用 `unittest` 的检查方法，不依赖会被移除的语句。`-OO` 还会删除文档字符串，因此也专门运行。`-B` 只是不写字节码缓存，不改变模型的数学内容。

有限检查的边界为：

- 关系：对象数0到3，两个可用表示标签，全部表示与全部布尔有向关系，共4,165例；独立枚举所有候选抽象表检验存在性
- 一元谓词：同样的对象数与标签，全部布尔谓词，共85例
- 多重集：两个原子，每项输入次数为0、1或2；共9个输入向量、81个有序输入对；检查324次重命名相容、324次投影相容、729个结合律三元组，以及324次倍乘分配
- 策略：刺激数0到3、两个输出，全部真实表与观测子集，共85种记录情形、228项逐点预测检查

这些数量由确定的有限枚举边界产生，也由实际运行输出报告。不是随机试验次数、样本量或认知测量。不同检查不能随意相加成一个仿佛有共同统计意义的总分。

一般结论的依据仍是前面的证明：纤维矩形恒定的充要条件、逐坐标加法与有限求和，以及未观察位置的独立选择计数。有限测试的作用是发现代码有没有违背这些定义。修改代码后必须重跑；旧日志不能证明新代码已经执行。
