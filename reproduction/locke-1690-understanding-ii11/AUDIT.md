# 洛克 II.XI 有限模型：独立代码审计

## 结论与边界

结论：本次冻结版本通过代码审阅、独立有限判定、三种解释器模式实跑、输入边界检查及语义故障注入。未发现尚未解决的实现错误。正文第3、4、6节的教学例子与实际输出一致。

这份审计只支持所列有限输入与接口规格下的实现结论，不代替一般数学证明，不是历史实验复现，也不提供人或动物心理能力的经验证据。运行环境实际为 CPython 3.12.14、Linux、x86-64；未实际测试其他 Python 版本，因此不能把文档的最低版本声明误当成多版本实测结果。

最终审阅文件、字节数与 SHA-256 见 [`audit/code_review.json`](audit/code_review.json)。代码、说明、正文相关部分或证据文件变化后，原审计不能自动继续适用。该清单不绑定其他审阅者仍可能更新的报告。

## 1 审阅范围与独立性

审阅输入为 `model.py`、`finite_checks.py`、`test_model.py`、`examples.py`、`run_checks.py`、`README.md`、`WALKTHROUGH.md`，以及[中文正文](../../papers/1690/locke-understanding-ii11.zh-CN.md)第3、4、6节的规格与例子。正文文件整体哈希用于防止版本错配，不表示本次代码审计独立认证了全篇的史料来源。

独立检查程序为 [`audit/independent_checks.py`](audit/independent_checks.py)。它只导入被测模型，不调用作者的有限检查函数来制造预期答案：

- 关系：枚举实际像集上的每张候选商表，将其展开为原对象域平方上的位掩码，再与所有输入关系逐一比对。另行检查冲突证书是否覆盖每一个坏矩形、是否重复，以及真假见证是否为声明的首个见证。
- 多重集：把向量展开为原子出现序列，以标准库 `Counter` 统计拼接、重复、重命名和过滤后的结果，与被测计数向量比较。
- 策略：独立构造每张完整表，枚举全部允许候选子集与部分观察函数，逐候选核对相容性。它覆盖受限类、空类与非空类，不只检查“所有函数都允许”的计数公式。

原作者的47项测试亦在三个模式下重新执行。独立计数公式另外核对 `finite_checks.py` 与 `examples.py` 报告的全部有限枚举数量。

## 2 三种模式的真实执行证据

在本复现目录核验冻结交付：

```bash
python3 -B audit/verify_evidence.py
```

若要重新执行全部检查，再核验本次输出：

```bash
python3 -B audit/run_audit.py
python3 -B audit/verify_evidence.py --current-run-only
```

重新运行会更新运行时间和证据文件，因而不再符合旧交付证据的哈希；`--current-run-only` 仍核对冻结的审阅输入及本次全部命令流，但不把新运行冒称为原先冻结的证据。若重新签发审计，应重新审阅并绑定新证据。

运行器只写入 `audit/`，不改作者的源代码、结果或原始日志。它依次调用普通、`-O`、`-OO` 三种模式，显式设置 `PYTHONHASHSEED=0`，并通过子进程记录实际优化级别。全部判定使用显式异常，不依赖会在优化模式下消失的普通 `assert`。

实际执行54条子命令：每种模式各18条，包括环境探测、作者测试、独立检查、作者有限检查、例子输出、12个语义故障变体及一个框架故障探针。三种模式均满足预期退出码：

- 原版代码的47项作者测试全部通过
- 扩展独立检查全部通过，三份独立结果逐字节相同
- 三份新生成的例子输出逐字节相同，并与已保存的 `results.json` 及作者三份例子日志逐字节相同
- 每种模式的12个语义故障均返回专用语义失败退出码2
- 故意缺失输入模块的框架探针均返回专用框架失败退出码3，未计为语义故障检出

命令、工作目录约定、环境覆盖、退出码、运行时间、输出长度及哈希均在 [`audit/execution_report.json`](audit/execution_report.json)。其中工作目录 `.` 指本复现目录；解释器路径记录实际运行时路径，不是假定可移植的安装位置。

完整证据按模式保存在三个顺序日志中：[`normal.log`](audit/logs/normal.log)、[`O.log`](audit/logs/O.log)、[`OO.log`](audit/logs/OO.log)。每条命令有独立元数据，标准输出和标准错误按明确字节长度分段，未删去空流或失败流的信息。验证器按长度重新提取全部54对输出流，检查哈希、退出码和文件绑定。故障变体源码在运行后删除；运行器保留精确替换定义，可由冻结原版重新生成。

## 3 独立有限检查覆盖

### 3.1 所有有向纤维对与实际像集

对象数为0到3，允许三个表示标签，枚举全部40张表示表与13,975张关系输入。其中3,475次可下降、10,500次不可下降；逐项核对18,852份坏矩形证书。按对象数分组的关系案例数为1、6、144、13,824；成功数分别为1、6、102、3,366。

同一范围的一元谓词共259例，其中163例可下降。标签未出现时不会被偷偷加进商关系域。另有四对象定向反例，使全部四个纤维矩形同时冲突，用来防止实现只返回一个见证或漏掉反向矩形。

特别覆盖：空对象域的唯一空商表、全假商表仍为成功、非对称关系、单射表示、全部冲突矩形、严格布尔值、表示的精确键集合、关系的完整有向对象对域、未知或空标签，以及一元表的完整性。整数0和1作为关系真值被拒绝。

### 3.2 次数、支持集与重命名碰撞

独立输入扩展为三个原子、每项次数0到2，共27个向量：

- 729个有序加法输入对
- 5,832次重命名，包括到两个目标名字的全部八张映射
- 5,832次投影，包括全部八个保留子表
- 2,916次倍乘分配及独立次数核对
- 19,683个结合律三元组
- 源、目标原子数各0到3的60张合法映射，检查单位向量及零向量所见的单射性判准

特别覆盖：重命名碰撞必须相加而非覆盖、重复输入次数累计、零次数不进入支持集、未知原子即使次数为零也拒绝、每条负次数均拒绝、空源与空目标的合法边界、非空源不能映向空目标、加法原子表必须一致、投影只能保留已知原子，以及直接构造时的规范排序和长度。

次数与倍数要求严格的非负内置整数。布尔值、浮点数、字符串、空值、负数及整数子类的接口边界均有明确检查；不会因为 Python 的布尔值也是整数子类就把真误当成一个单位。

### 3.3 候选相容、空空间与域限制

对0到3个刺激、两个响应，枚举每张完整表的全部候选子集和所有部分观察函数，共7,070个候选类／观察案例、21,036次逐刺激查询。其中5,770次查询面对空版本空间，12,060次为非空一致预测，3,206次为尚未确定。

特别覆盖：严格筛选每条记录、重复观察幂等、矛盾记录拒绝、候选表的有序刺激域与响应域匹配、查询越界拒绝、空候选类、合法记录排除全部候选、空刺激域恰有一张空表，以及不同名字但行为完全相同的两个描述仍不可由观察区分。空版本空间不产生任何“空泛保证”的具体答案。

独立输入拒绝检查共96例，另有针对语义故障的短反例。以上不同检查具有不同边界和计数口径，不合并成一个仿佛有共同统计意义的总分。

## 4 作者报告数量的独立复核

对作者实际采用的两个标签边界，独立计数得到：

- 关系：15张表示表、4,165张关系输入、141次成功、4,024次失败
- 一元谓词：85例、45次成功
- 多重集：9个输入、81个有序输入对、4张重命名、4个保留子表、324次重命名、324次投影、729个结合律三元组、324次倍乘分配
- 策略：85个真实表／观察子集案例、228次逐点预测检查

关系案例数直接计算为：

```math
\sum_{n=0}^{3}2^{n+n^2}=4165.
```

给定表示后，成功关系数为实际像集平方上的布尔表数；审计对全部表示分别求和，得到141。策略原始检查枚举“真实表与已见位置子集”，相同观察可从多个真实表产生，因此其85例不是85种互不相同的观察；独立扩展检查采用部分函数口径，两种计数不可混读。

## 5 正文、说明与机器输出的对应

- 正文第3.3节：三卡是白色编号1、白色编号2、蓝色编号3；同色关系可下降，编号严格先后不可下降。输出使用甲乙为真、甲甲为假，正文明确允许该见证，且走查解释了正文也可选乙甲。
- 正文第4.3至4.4节：一个单位与一打分别为1和12；红2蓝1、红1蓝2改名后同为3个单位。投影例的红2蓝1与红2蓝7则都留下红2，且不错误宣称总次数保留。
- 正文第6.4节：白圆、白方、蓝圆、蓝方四刺激；只见白圆为1、蓝圆为0。16张完整二值表留下四张，白方仍有0与1两种可能。新增白方为1只会在所示两个具名候选中留下颜色规则；在全部16表的候选类中仍有两张。
- 文档现已明确区分矛盾记录在数学定义下导致空版本空间，与接口在入口抛出 `ValueError` 的选择。合法无矛盾记录与受限候选类不相容时，接口正常返回 `empty_version_space`。
- 函数总数按不同外延表计；名字不同但表相同是重复候选描述，不能拿来增加不同函数数目。

所有数值及结构化例子字段都由独立运行器核对；历史定位及本文与原章之间的解释关系仍应结合来源审阅阅读。

## 6 语义故障注入与框架错误区分

每次只对原版模型做一处明确文本替换，不修改原文件。12个故障分别是：冲突时接受残缺商表、只报告首个坏矩形、把有向标签对强行对称化、把空商表当失败、允许整数冒充关系布尔值、用逐项最大值代替加法、覆盖重命名碰撞次数、把零次数放进精简支持输出、接受布尔次数、保留不相容策略、从空候选类给出预测、允许矛盾观察。

每个故障都在三个模式中被独立检查以具名语义反例发现，共36次预期语义失败。具体替换前后内容、变体哈希和首个失败检查名称均在执行报告中，不以“进程非零退出”笼统冒充检出。

另行故意指定不存在的模型输入。三个模式均被识别为 `framework_error`，而非 `semantic_failure`。此类框架错误计入语义检出的数量为零；因此模块加载失败不会虚增变异测试成绩。

## 7 保留的限制

- 这是有边界的穷举与有针对性的故障注入，不是对任意规模、任意 Python 对象或所有可能程序变异的机械证明。
- 公共函数按文档声明的有限字符串域及表类型使用；未把恶意自定义映射、无穷迭代器或资源耗尽输入当成本教学接口的承诺。
- 策略类由调用者指定，正确预测只在真实策略属于允许类且观察无误的条件下有保证。
- 各模式是在同一实际解释器版本中执行；没有跨系统、跨版本性能结论。
- 审计不改变任何源代码，也未进行远程写入、发布或安装依赖。
