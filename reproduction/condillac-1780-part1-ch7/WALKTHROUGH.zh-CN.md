# 从一份观察记录走到一份可检查的证明

本讲解对应 `python demo.py` 的实际 JSON 输出；完整输出保存在 `results/demo.json`。所有名字和颜色/形状材料案例都是现代教学构造，不是原书实验材料。先读 `MODEL.zh-CN.md` 的范围声明，再将程序结果用于解释历史文本。

## 1. 先固定世界，而不是让程序猜世界

演示目录只有三个对象：

| 名字 | color | shape | material |
|---|---|---|---|
| $`a`$ | red | round | wood |
| $`b`$ | red | round | metal |
| $`c`$ | blue | square | wood |

`Catalog` 明确列出三个特征和各自值域。程序拒绝缺少material的完整对象、域外值、重名对象和重复特征。这一步给后续判断建立可检查的边界；它没有从原文推导出一个真实世界本体论。

## 2. 注意：只把部分性质带进当前任务

```python
left = attend(c, "a", ("color", "shape"))
recalled = attend(c, "b", ("color", "shape"), "recalled")
```

结果是两个记录，各含color=red、shape=round；前者来源是current，后者是recalled。两者都没有记录material。$`a`$、$`b`$及其材料没有因此从目录消失。

这里的双重注意，是同时保留两份记录供比较；不是把两个单对象选择函数依次复合。recalled 标记使“对象不在眼前仍可比较”成为显式数据来源，但模型没有时间轴、记忆检索或错误回忆。

## 3. 比较与判断：未知必须留在输出中

```python
compare(c, left, recalled, "color")     # "equal"
compare(c, left, recalled, "material")  # "unknown"
```

color在两份记录中都有值，且相同。material虽然在完整目录中已知，却在两份观察中缺失，所以compare不借目录偷偷补齐。程序必须保留unknown，而不能把缺失当成相等，也不能把“没看见相同”当成不同。

这是一个定义清楚的判断过程；不是对原文“比较便有判断”这一心理强断言的证明。

## 4. 反思：逐项比较不能跳成整体同一

```python
reflect(c, left, recalled, ("color", "shape", "material"))
# (("color", "equal"), ("shape", "equal"), ("material", "unknown"))
```

若只按color、shape给完整目录分组，得到($`a`$,$`b`$)与($`c`$)。若纳入全部三个特征，则是($`a`$)、($`b`$)、($`c`$)。$`a`$、$`b`$在已选性质上相似，却有隐藏材料差异。

`equivalence_classes` 调用的是完整目录，不是上面的部分观察。它的等价关系证明以“选中坐标全都已定义”为前提。更多特征只会细分旧类，不能把原来不同的类合并。即使全特征相同，模型也不证明两个对象名字表示同一个东西。

可做的小练习：将特征集改成空元组，三个对象会进同一个类。这不是它们毫无差异，而是我们没有提出任何区分条件。

## 5. 想象：先列组合，再独立问有没有见证

把$`a`$的当前color/shape和$`c`$的回忆color/shape交给imagine，质量池分别包含red、blue与round、square。实际输出四个组合：

| 组合 | 目录见证 |
|---|---|
| blue, round | 空 |
| blue, square | $`c`$ |
| red, round | $`a`$、$`b`$ |
| red, square | 空 |

组合可枚举不等于存在已知实例。没有目录见证也不等于世界上不可能有实例。程序返回质量组合和见证两项，而不把两种问题藏在同一个真假答案里。

新增观察若没有新的质量值，不会增加组合数，因为每个质量池先去重。若某个所选特征完全没有观察值，程序抛出ValueError；它不能凭空为那一维补一个质量。若乘积大于4096，程序在实际枚举前拒绝继续，以保证教学运行成本有上界。

## 6. 推理：看到中介，而不只看到最终答案

第一组推理使用事实$`p`$，以及规则$`q\to r`$、$`p\to q`$。故意把$`q\to r`$放在前面，迫使程序继续扫描到固定点：

```text
p       初始事实
q       使用规则pq，前提p已出现
r       使用规则qr，前提q已出现
```

`closure` 返回的实际证明序列是：

```json
[
  {"atom": "p", "rule_name": null},
  {"atom": "q", "rule_name": "pq"},
  {"atom": "r", "rule_name": "qr"}
]
```

`verify_certificate` 逐步检查每个规则真的在Theory中、结论匹配、前提早已出现，并确认目标在序列中。把$`r`$挪到$`q`$前、把qr改成不存在的规则名、或把$`r`$伪装成初始事实，都会被拒绝。这个检查器不重新求闭包。

`semantic_oracle` 独立枚举三个原子的8种真值赋值。只有$`p`$、$`q`$、$`r`$全真的赋值满足事实和两条规则，所以输出全部三个被蕴涵的原子，模型数为1。有限穷举为本例的推导提供另一条检查路径；它没有把原书的语言改写成经作者认可的形式系统。

## 7. 缺桥不是算法失灵

第二组的三个名字是air_has_weight、pressure_bridge、column_supported。规则是：

```text
air_has_weight AND pressure_bridge -> column_supported
```

仅给air_has_weight，实际输出：被蕴涵的原子只有air_has_weight，满足赋值有3个。它们分别允许：桥假且支撑假、桥假且支撑真、桥真且支撑真。因此“支撑”不在所有模型中成立，不能推出。

把pressure_bridge作为额外事实后，三原子全被推出，模型数变为1。注意这一步是添加了假设，不是从“空气有重量”中无代价地产生物理知识。代码没有计算汞柱高度，也没有对pressure_bridge所概括的物理条件提供经验证据。

第三组只给$`p\to q`$、$`q\to p`$，没有事实：输出空证明、空蕴涵集，模型数为2，即全假与全真。循环不会自己产生一个起点。

## 8. 脚注：集合推理有效，仍可不适合教学

`subset_syllogism` 检查小集包含于中集、中集包含于大集，以及结论小集包含于大集。演示非空实例的premises、conclusion、implication全为true。

空small实例同样如此，但small_nonempty=false。可见普遍包含命题本身不保证任何对象存在。如果前提不成立，整体条件式还可能空真，所以要同时看premises而非只看implication。

原文脚注开头的“A包含B”与稍后的“A包含于C、C包含于B”方向不同；本API特意不用原文字母冒充同一个方向。脚注的否定式在模型文档中有单独集合证明，但没有程序接口。脚注对这种三段论教学作用的批评，不会使上述集合论推理无效。

## 9. 如何检查这些讲解没有脱离代码

```sh
python verify.py
```

检查`results/run-summary.json`中的all_passed，再看三个测试日志均为18个方法通过，以及`results/mutations.json`中killed=8、total=8。变异包括把unknown错判成equal、忽略所选特征、虚构见证、把合取改成析取、凭空加入证明、跳过证书前提、忽略规则结论和倒转语义蕴涵。每个变异都必须造成真实行为测试失败；语法错误或崩溃不算被测试正确抓住。

这些检查有明确边界：1024个两原子理论是那个有限规模的完整穷举；200个三原子案例是固定种子的抽样；两者都不能替代数学证明，也不能保证任意未来改动安全。`-O`和`-OO`测试用来确认必要验证没有寄托在可被优化删除的assert语句上。需要扩展到带噪声观察、时变对象、否定推理或真实物理时，必须重新定义模型和相应证明，而不是悄悄换一个例子就宣布已经覆盖。
