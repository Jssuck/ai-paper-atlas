# 精确结果与解释

以下是合成例子的精确结果，不是经验测量、历史发现或人类学习结论。完整机器可读输出见 `examples/expected_results.json`。

## 正文例子的精确对应

这些结果位于 JSON 键 `article_examples`，与下方补充变式分开。

- `00, 01, 10, 11` 的异或标签为 `0, 1, 1, 0`；各两次谓词测试，编译共八次模型内谓词测试，查表存四个条目
- 改错 `11` 叶后，树和表标签均为 `0, 1, 1, 1`；均匀错误率均为 `1/4`
- 保留第一位并判断第一位：源风险为零
- 同一表示判断第二位：沿用解码器风险与最低目标风险均为 `1/2`；细化为完整二位表示后，最低风险为零
- 单纤维标签 `0, 0, 1`，权重 `2, 1, 3`：总质量六，最低风险 `1/2`，并列按字典序选择标签 `0`；分开第三个对象后最低风险为零

下方补充树总编译次数为六，不是八；补充加权目标风险为 `3/8`，不是 `1/2`。这些有意构造成不同例子，不能混为同一次运行的相同总体。

## A. 完整编译补充例

树对 `a, b, c, d` 输出 `drop, drop, drop, keep`，谓词测试数为 `1, 1, 2, 2`。编译表逐点相同，每次成功查询约定计一次抽象查表，存储四个输出条目。

外部真标签为 `drop, drop, keep, keep`。所以 `c` 编译后仍错：两次谓词测试变成一次抽象查表，均匀错误率仍为 `1/4`。平均计数为 `3/2` 次谓词测试对一次查表；这是约定操作比较，不是时间测量。根叶例需要零次谓词测试，故不是处处更便宜。

`b, d` 的部分表复制原树输出，只含这两个键，并不从外部真实训练标签拟合。`a, c` 缺少记录，查询抛出 `UnknownInput`。两棵测试树在已观察 `d` 上一致、在未观察 `c` 上不同，说明这些记录本身无法唯一确定未见响应。

## B. 表示与迁移补充例

- 解码器 `A → keep, B → drop` 的源风险：`0`
- 加权目标总质量：`8`
- 沿用解码器的目标风险：`3/8`
- 目标全域结构充分性：否
- 最优目标解码器：`A → keep, B → drop`
- 最低目标错误质量：`3`；最低风险：`3/8`
- 纯纤维但标签对调的目标：结构充分，沿用解码器风险 `1`，最低风险 `0`
- 零权重碰撞目标：全域不充分，正权重支持集充分，最低风险 `0`
- 零权重例确定性解码：`A → keep, Z → drop`

第一个加权目标恰好使沿用解码器最优，标签对调例表明这不是保证。源风险零和目标表示充分，都不能单独保证沿用解码器正确。

## C. 复制与传播

一百份精确副本保留一个来源标识，不是一百次独立观察。

链上首次到达轮次为 `A:0, B:1, C:2, D:3`。增加从 `A` 发出的捷径后为 `A:0, B:1, C:1, D:1`。最终仍是 `A, B, C, D` 四个持有者，孤立顶点未到达。正确与错误算术断言的传播快照完全一致。

## 验证记录

执行 `python3 verify.py` 可重新生成并覆盖本地验证日志。记录的本次运行在三种模式中各通过20项测试：

- 普通 Python：`logs/normal.log`
- Python `-O`：`logs/optimized.log`
- Python `-OO`：`logs/double-optimized.log`

各模式的示例输出都与固定预期文件逐字节一致。解析生产代码语法树，发现 Python `assert` 语句数量为零。`logs/environment.json` 记录实际解释器名称和版本、平台、UTC 时间、源码及预期输出哈希；公开目录和命令使用相对显示，不包含私有机器路径。

穷举部分为202棵树的全部四个输入、768个总体与全部二元解码器、4,096个图与种子组合和独立最短路径结果。另有正文三个手算例的独立精确断言。这些是有限回归检查；一般结论和限制由 `MODEL.md` 证明。
