这些数来自本次真实执行，不是作者单元测试数量；作者每模式21项测试另见原日志。没有把未运行的网络服务或证明助理写作已通过。

## 逐代码审查要点

`given` 精确检查索引类型、范围及所述前提；无法用 `True` 冒充索引1。`atom` 对语句种类、元数和项名作检查。每个证明节点限制允许字段，未知“信任我”规则不会被接受。

`raa` 仅支持 `NO` 与 `SOME` 互为矛盾的目标，不支持任意公式。引入新标签、禁止覆盖当前作用域；子证明须得 `FALSE` 且依赖该标签，之后只移除该标签。其他依赖继续传播，最终要求没有未卸除的假设。拒绝空卸除是格式限制，不是对经典逻辑一般规则的否定。

普通规则以项位精确匹配而非模糊语义匹配；例如 `clash` 要求相同顺序的同一项对，语义上对称的关系需先显式换位。这是有意限制的证明语言，不应把拒绝某些等价证书说成数学反例。

局部规则的一般理由是包含传递、同一对象迁移及交集对称；反证以经典二值解释为依据。对有限证明树按结构归纳可获得这些规则的健全性说明，但本审查没有在证明助理中形式认证该元定理。有限 oracle 未发现反例并不独自证明无限对象域上的定理。

## 保留限制

- 语义输入前提是受信假设，校验器不检查其现实来源或总体相容性。不相容背景的形式后果不等于新的事实知识。
- 深度64、访问10000节点是程序界限；不是任意大有效证明都能接受。输入前提总长度未设置面向恶意网络流量的全局限额，代码不宣称生产级资源隔离。
- `holds` 要求集合值为 `frozenset`，未要求显式公共论域对象；它只处理给定集合的外延关系，不认证数据采集完整性。
- 两世界例为现代“分别存在情形不可直接合并”的诊断，不认证古代可能语义；本程序没有世界可达关系、双向偶然或完整模态规则。
- 没有完整证明搜索或所有证书穷举。本报告主要核健全性及接口边界，不宣称语法完备。
