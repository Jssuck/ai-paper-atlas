# 一组图形怎样分出名称、真值与证明？

先读例子，再运行 `python3 -B demo.py`。下文的每个输出均来自这个命令，而不是手工模拟程序日志。`true/false` 是 JSON 布尔值；`null` 对应 Python 的 `None`，含义取决于所在字段。

## 1. 明确世界，再写名称

宇宙依次只有四个对象：红三角、蓝三角、红方块、蓝方块。它们是示例的对象标识，不是程序通过图像识别观察到的形状。类名按如下顺序定义：

| 类名 | 外延 |
| --- | --- |
| 三角形 | 红三角、蓝三角 |
| 图形 | 红三角、蓝三角、红方块、蓝方块 |
| 红色 | 红三角、红方块 |
| 三边形 | 红三角、蓝三角 |
| 空类 | 无对象 |

其中“三角形”和“三边形”是此宇宙中的等外延名称；“三角形”与“红色”相交。外延并不是一个互不相交的分类表。

现在只记录三条断言边，顺序如下：

1. 三边形 → 三角形
2. 三角形 → 图形
3. 空类 → 红色

图故意没有记录所有正确包含。先逐条检查：第一条两端外延相同；第二条两个三角形都在图形中；第三条没有空类成员可能违反它。全图有效。

## 2. 一个真正可核验的推理链

问“三边形是否都属于图形？”

- 起点“三边形”进入队列，先沿第一条边发现“三角形”。
- 再处理“三角形”，沿第二条边发现“图形”。
- 回溯前驱得到“三边形 → 三角形 → 图形”。路径有三个名称、两条边。
- 红三角与蓝三角逐个经过两个包含前提，均属于图形。

实际字段是：有限域包含 `true`，图证明 `["三边形", "三角形", "图形"]`，反例 `null`。

另一问“三角形是否都属于三角形？”不需要自环。返回 `["三角形"]`，长度为 0。这种自反性不能因“没有显式边”而被漏掉。

## 3. 没有图证明，命题仍可能为真

问“红色是否都属于图形？”

- 扫描外延：红三角、红方块都在图形中，故语义包含成立。
- 图中的“红色”没有出边，因此找不到到“图形”的路径。
- 输出：有限域包含 `true`，图证明 `null`，反例 `null`。

第一个 `null` 说“未在图中找到证明”，第二个 `null` 说“有限宇宙中不存在违反包含的对象”。两个空值不是同一判断。

添加有效边“红色 → 图形”会让这道题获得图证明。无需修改任何名称、对象或外延；变化的是已经编码的前提。

## 4. 真的失败要指出哪个对象

问“三角形是否都属于红色？”

1. 红三角在红色中，没有失败。
2. 蓝三角不在红色中，因此它就是首个见证。
3. 输出：有限域包含 `false`，图证明 `null`，反例 `"蓝三角"`。

反方向“红色是否都属于三角形？”也失败，见证是红方块。两类确实共享红三角，但共享一个对象并不使任何一方包含另一方。

把红三角当作“三角形”的单个代表，只问它是否红色，`prototype_accepts` 返回 `true`。如果据此断言“所有三角形都是红色”，蓝三角立即推翻该规则。代表检查测的是一个对象；包含检查量化的是整个前件外延。

## 5. 同义名称，原来并不在同一个 SCC

原图中“三边形”可以到“三角形”，反向却无路径。虽然二者外延相同，它们仍在不同强连通分量。原图返回：

```text
[["三角形"], ["图形"], ["红色"], ["三边形"], ["空类"]]
```

添加有效的返回边“三角形 → 三边形”，两者相互可达，返回：

```text
[["三角形", "三边形"], ["图形"], ["红色"], ["空类"]]
```

此时只是报告它们属于同一个 SCC，系统仍有五个名称、四个对象。程序没有删除同义词，也没有把两个名称变成同一个字符串。

## 6. 空类中的全称真不说明“有一个”

“空类是否都属于三角形？”的语义答案是 `true`，反例 `null`；图中却没有这条路径，所以图证明也是 `null`。

对“空类 → 红色”，图有直接有效边，但仍找不到一个空类对象作为例子。假如把整个宇宙改为空集，所有外延都空，这条包含仍然成立。“所有 A 都是 B”不能单独推出“存在 A”或“存在 B”。

程序也拒绝给空类选代表：`prototype_accepts` 的前提是代表确实属于前件，不接受随便指定一个域外对象。

## 7. 改名之后保持什么？

将标签依次改成 `(A, B, C, D, Z)`，即三角形→A、图形→B、红色→C、三边形→D、空类→Z。外延与边同步传递。

- 原来的“三边形 → 三角形 → 图形”现在是 `D → A → B`。
- 对象数仍为 4。
- “A 都是 C”仍为假，见证仍是蓝三角。
- 原来无路径但为真的“红色 → 图形”，改名后 `C → B` 仍无路径但为真。

如果只把显示文字改了，却把旧解释贴错位置，那是解释变化，不属于双射改名定理。把两个名称合并也不是这里允许的改名。

## 8. 一条坏边会触发全图拒绝

向原图添加“红色 → 三角形”。外延检查返回：

```text
[["红色", "三角形", "红方块"]]
```

新增边是错的，红方块就是见证。原始图搜索仍能找到“红色 → 三角形”，因为 `find_path` 只看图，不看真值。

甚至换问完全自反的“图形 → 图形”：原始搜索返回 `["图形"]`，但 `prove` 仍抛出 `InvalidGraph`。这不是说“图形不是图形”，而是本程序采用全图审核，任何坏边都会阻断认证。对于一条不经过坏边的路径，另做局部认证可能成功；这是未实现的另一设计，不能暗中替换本程序的接口约定。

把这条坏边两端名称换得再工整，也不会使红方块变成三角形。

## 9. 练习与完整答案

### 练习一：补一条边

不改变外延，使“红色 → 图形”可证明，最直接应补什么？

答案：补同名直接边“红色 → 图形”。它有效，因为两个红色对象都属于图形。已有语义真值不变；图证明从不存在变为一边路径。补“三角形 → 红色”则是坏边，会触发全图拒绝。

### 练习二：无路径可以推出不包含吗？

答案：不可以。原例“红色 → 图形”真但无路径；“三角形 → 红色”假且无路径。相同的图搜索结果对应两种语义情况，需查外延及反例。

### 练习三：名称同义意味着 SCC 相同吗？

答案：不意味着。原图“三角形”“三边形”外延相同，却缺反向路径。有效图的双向可达能够保证等外延；图相对于外延完备足以保证反向结论，但不是必要条件。对于有效图，只要也必须让每个等外延类内部的名称互相可达，就能让两种分组一致；不同外延之间仍可遗漏真实包含。

### 练习四：空类到任何类都有效，是否应自动补所有边？

答案：这会是一种可选的图补全功能，但本程序没有自动这样做。语义真、断言已记录、路径可推出是三个可分别检查的状态。无论补不补边，空类仍没有对象。

### 练习五：单代表方法有没有成功的特殊情形？

答案：若前件确为单元素集合且代表就是它，检查该对象足够；或另有独立论证保证全类在目标属性上一致，也能使用那份额外论证。只有一个正例本身不足以保证这个前提。空前件没有可选代表。

### 练习六：一个看起来无关的坏边为什么也阻断认证？

答案：因为 `prove` 的契约先检查整个图。它牺牲部分可用性换取简单、显式的全局前提。若只需局部路径安全，应设计并证明另一个接口；不能把全图拒绝解释为查询命题为假。

### 练习七：怎样得到关于全部现实三角形的结论？

答案：本程序不能仅凭这四个对象给出该结论。必须另外建立真实对象域、解释的正确性和适当数学或经验论证。通过小域测试只能核验程序，不会把有限样本自动变成现实全称真理。
