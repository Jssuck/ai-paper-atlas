# Condillac《La Logique》II.V：类名与推理图

这是原创、低成本、现代外延教学模型，不是 Condillac 算法的复原。历史参照采用 [1798 年印本正文 pp. 131–140](https://archive.org/download/b28772581_0022/b28772581_0022.pdf#page=139)；目录中的 1780 标识作品年代。发布文件不附原文扫描件或逐段译文。

核心问题：类有了名称，是否就能保证关于它的推理正确？程序把四件事分开：对象、类名的外延、图中记录的包含前提、可沿图给出的证明。

## 从这里开始

1. 阅读[逐步手算与七道有答案练习](WALKTHROUGH.zh-CN.md)。用四个彩色图形对象，分别看有效链、遗漏真关系、具体反例、同义类名、空类和误导性的单个代表。
2. 阅读[完整定义、一般证明与历史边界](MODEL.zh-CN.md)。重点区分图预序与语义包含预序。
3. 运行示例和验证。所有数据都在本目录，不需网络、账户、模型 API 或第三方依赖。

## 运行环境与命令

仅使用 Python 标准库，语法要求 Python 3.10 或更新。实际验证环境为 CPython 3.12.14，未声称检验其他版本；完整解释器与操作系统版本、参数及实际命令见 [`evidence/verification.json`](evidence/verification.json)。工作目录统一发布为 `.`，表示此附件目录；实际执行的绝对目录为便携发布而省略。主机名、账户秘密及无关环境变量不记录，供应商解释器路径保留。

在本目录运行：

```bash
python3 -B demo.py
python3 -B verify.py
python3 -B -O verify.py
python3 -B -OO verify.py
```

`-B` 避免字节码缓存。三个验证命令均实际执行完整专门测试、同一有限穷举和语义变异实验；没有以“优化模式不支持”为由跳过。实现、校验器和测试文件不含 Python `assert` 语句；用明确异常、`unittest` 方法和运行时检查，`-OO` 删除文档字符串也不改变行为。

一次重新产生所有证据：

```bash
python3 -B record_evidence.py
```

它使用当前 `sys.executable` 启动六个子进程：三种模式各运行验证和示例。保存退出码、完整日志、日志散列、运行前后源码与文档散列；实际命令包含解释器绝对路径，便于核查所用环境。三份示例输出必须逐字相同，三份验证的穷举与变异结果也必须相同。每个验证子进程在日志开头自行报告真实的 `sys.flags.optimize`；记录器另核验它们确实为 0、1、2，而非仅根据命令标签推定。单元测试耗时可不同，不将其当作性能基准。

## API 的关键约定

`ClassSystem` 的输入是不可变的对象元组、类名元组、按类名排列的外延元组、断言边元组。每个外延是 `frozenset`；类名至少一个，对象宇宙可以为空。允许空类、同义外延、交叠与环。

- `includes(a,b)`：在声明的有限宇宙中，检查前者外延是否包含于后者。
- `witness(a,b)`：失败时给出对象顺序中的首个反例；`None` 表示包含成立。
- `find_path(a,b)`：只查图，返回最短路径或 `None`。自反查询有零边路径。
- `violations()`：列出坏边与反例。
- `prove(a,b)`：先检查全图的每条边；存在任何坏边就抛 `InvalidGraph`，否则返回图路径或 `None`。这里的 `None` 不表示命题为假。
- `components()`：报告图的强连通分量，不按同义外延自动合并标签。
- `rename(new_labels)`：双射改名，同时传递外延与边，不产生对象。
- `prototype_accepts(...)`：仅检查一个属于前件的代表是否属于后件；特意用于展示其不能普遍替代全称检查。

全图认证是明确的设计选择：即使坏边与当前问题无关，`prove` 也拒绝。该拒绝不等于当前命题为假。局部路径认证和自动补边均未实现。

## 精确验证域与计数

每种模式运行 31 个专门测试方法，覆盖输入错误、空宇宙、自环、重命名交换、搜索平局、非字典序见证、无关坏边及代表错误等。

穷举使用 2 个对象、3 个类名。每个外延有 $`2^2=4`$ 种选择，外延赋值共 $`4^3=64`$ 种；3 个类名有 6 个非自环有向边位，图共 $`2^6=64`$ 种。总计 $`64\times64=4096`$ 个上下文。自反可达来自零边路径；显式自环在专门测试中检查，不在穷举边位中重复。

| 检验类别 | 精确计数 | 含义 |
| --- | ---: | --- |
| 外延赋值 | 64 | 含空类、同义和交叠 |
| 图上下文 | 4,096 | 所有赋值与所有非自环图组合 |
| 全边有效图 | 904 | 按位掩码直接检查每条边 |
| 含坏边图 | 3,192 | 全图认证必须拒绝 |
| 可达性查询 | 36,864 | 每个图的 9 个有序标签对 |
| 语义包含及见证查询 | 36,864 | 与上项是同一批查询的另一检查 |
| 有效图认证查询 | 8,136 | 904 个图 × 9 个对 |
| 有效图中真但不可达的查询 | 1,620 | 不完备性的有限实例计数 |
| 全部图中的失败包含查询 | 10,752 | 重复图中的相同语义也重复计数 |
| 有效图中双向可达有序对 | 3,564 | 含自反对，均须等外延 |
| 有效图双射改名版本 | 5,424 | 每图 6 种新标签排列 |
| 改名后的查询 | 48,816 | 每版本 9 个有序对 |

这些是相关检查的计数，不是互相独立的实验，不能相加作总基准分数。验证器检查实际计数与表中目标一致，防止无声缩减枚举域。

语义参考使用整数位掩码包含和逐位反例搜索，不调用待测 `includes` 来构造期望值。可达性参考使用 Floyd–Warshall 距离矩阵，不使用待测 BFS；同时检查返回路径确实由输入边组成、没有重复名称且长度最短。SCC 期望值也从独立距离矩阵产生。改名检查逐标签传递路径及语义真值。

## 变异实验：功能错误与执行故障分开

在内存中各自替换源码的一处已确认唯一片段，再编译、加载并运行十个固定语义探针。磁盘上的实现不被改写。十种语义变异分别是：

1. 用首个代表代替全称包含
2. 用相交代替包含
3. 用严格包含代替非严格包含
4. 擦除具体反例
5. 删除零边自反路径
6. 反转所有边方向
7. 只搜索直接边
8. 绕过全图有效性门槛
9. 把等外延名称误当作同一个图 SCC
10. 改名时反转外延对应

实际结果为 `killed_semantic=10`、`survived=0`、`harness_error=0`。这是手选十种变异的结果，不是一般覆盖率。每个失败探针及信息在三份验证日志中逐项保存。

另有三个不计入上述数字的控制：原源码必须存活；故意语法错误必须归类 `harness_error`；故意除零也必须归类 `harness_error`。合法输入上的错误返回值，或在预先已知有效图上错误抛出规定的 `InvalidGraph`，属于可识别的语义违约；其他异常记作执行故障。检查失败的明确异常还另有一次假条件控制。任何误分类、语义变异存活或意外故障都令整个验证退出失败。

以上是实现作者编写的参考算法与实验；另行审查的方法、结果与证据单列在[独立代码与教学模型复核](independent-review/review.zh-CN.md)。

独立审查另写 DFS 简单路径枚举参考，不使用作者的 Floyd–Warshall 参考来生成路径期望值。它覆盖四类全部 4,096 个无自环图的 65,536 个有序查询，并补查自环组合、全部菱形边顺序、三对象两类的 1,024 个语义上下文及有效/无效图的改名。此新增范围与作者检查分开记录；它还复核原有数字、示例字段及证据散列，不把重复核对包装成新增覆盖量。实际三模式独立命令和日志见该报告。
