## 核验方法及真实结果

[独立脚本](code-review/check_independent.py) 不用作者的闭包求期望值：四标签全部含自环的 65,536 个有向图以布尔 Warshall 矩阵给出正长度闭包。它没有预先补单位矩阵，因而能检查环产生自关系与无环不默认补自反边的区别。

证书 oracle 用九位整数记录已知边和实际产出的结论位集。全部三标签输入图、单步三元组与目标共 124,416 次；全部三标签无自环输入图、两步有序三元组与目标共 419,904 次。每步输入必须在此前状态中出现，最终目标必须在产出集合中；前向引用、错误接合、仅存在输入目标及已得到目标后追加非法步骤均不能被放过。这是对作者 API 的约定核验，不是声称逻辑上所有有效证明都必须再次推导一个已经给定的目标。

另检查 n=2…23 的 22 个链规模的**具体项对集合**、k=0…6 的 197 种满二叉树形、共享子树按出现展开，以及 12 个格式或深度异常用例。树叶只是已声明假设，不核外部数据库真实性；深度 200 限制是实现保护。

正常、`-O`、`-OO` 三模式实际执行均通过，结果 JSON 逐字一致。见 [normal](code-review/results-normal.json)、[O](code-review/results-O.json)、[OO](code-review/results-OO.json)、[命令](code-review/commands.txt)、[环境](code-review/environment.txt) 和各模式 stderr 文件。失败检测使用显式异常，不会因 Python 优化移除。

## 人工检查要点

- `chain_report` 按跨度递增安排证书，所需较短关系已先出现；严格不同项名检查与通用闭包分离。
- `closure` 每轮仅加入有限标签集上的新项对，达到不动点终止；本审查不声称其平方嵌套实现对任意大图资源可行。
- `verify_certificate` 先验证格式再按给定顺序验证有效性；冗余正确步骤可接受，不能误称最短证书判定器。
- `proof_tree_stats` 每次递归按出现计数，不对对象身份去重；源码和 README 均明确这不是 DAG 不同节点计数。
- 原文历史语言与现代实现分开；正文的内部插入分类解释、分支反例、自反语义边界与实现一致。
- 作者模型仅实现全称肯定包含的传递闭包，不处理否定、特称、模态、归纳或真实资料来源。
