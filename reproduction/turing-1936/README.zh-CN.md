# 图灵计算模型：可执行教学复现

核验日期：2026-10-09。性质：概念与小机器的教学复现，不是完整历史通用机的复制，也不是不可判定性定理的实验验证。代码和测试全部使用 Python 标准库，没有安装依赖。

## 1. 一手来源与复现边界

已阅读原文第1–3节（原刊231–234页）的机器、输出和 circular/circle-free 定义以及交替序列示例：[Turing 原论文扫描件](https://www.cs.virginia.edu/~robins/Turing_Paper_1936.pdf)。原文区分结果位与辅助符号；circular 包括不停移动却不再输出结果位的机器。第233页交替序列例保留间隔格。

这里的 `alternating_spaced()` 对齐该例的四阶段与间隔布局，状态改名为 p0、gap0、p1、gap1。`alternating()` 则是明确标注的两状态简化。其余例子和有限枚举均为新编教学构造。未逐项复现原文通用机、标准描述编码、判定问题公式或后续勘误。

## 2. 明确定义被执行的模型

配置 C_t = (q_t, h_t, τ_t, o_t)：

- q_t 是有限状态集 Q 中的控制状态。
- h_t ∈ ℤ 是读头坐标；这里用向左右无限延伸的一条工作纸带。
- τ_t : ℤ → Γ 是纸带内容；Γ 有限且含空白 `_`。Python 字典只存非空白格，缺少的键解释为空白。
- o_t 是已经产生的二进制输出串。它是观察记录，机器不能读取、回退或改写它。
- 初始状态为指定 q_start，h_0=0，τ_0 全空白，o_0 为空串。

转移表是有限的部分函数：

δ(q,a) = (q′, b, d, e)，d ∈ {−1,0,1}，e ∈ {空串,0,1}。

一次转移同时规定：在旧读头位置写 b，读头移动 d，控制状态变为 q′，把 e 追加到输出。若当前状态和符号没有规则，则停止。

这是现代单工作带输出转导器记法。显式 `emit` 是为审计输出而添加的注释式通道，不是原文逐字模型，也不是机器可读取的第二条纸带。不得把本模拟器称作原文通用图灵机。涉及交替序列的小例子同时在工作带写下对应位；其他例子允许输出与工作符号分离。

实现返回两种观察状态：

- `halted`：末配置没有规则，包括恰好在步数上限抵达无规则状态。
- `cap_reached`：末配置仍有规则，仅因观察预算用完而停止模拟。不能将其解释为“不停机”的证明，更不能解释为 circle-free。

计步只统计成功执行的转移，不把检测缺失规则算作一步。trace 的第0行是初配置。

## 3. 可手算、可检查的不变量

从空白纸带执行 t 次转移后：

1. |h_t| ≤ t，因为每一步位移绝对值不超过1。
2. 非空白格数 ≤ t，因为一次最多新增一个非空白格；擦除时从字典删除。
3. 0 ≤ |o_t| ≤ t，且 o_t 是 o_(t+1) 的前缀，因为每次只追加零个或一个结果位。
4. 给定配置与规则，下一配置唯一。两次从同一初态重跑产生相同有限轨迹。
5. 读头移动后读取的是新格子；写入发生在旧格子。这一先后关系可用负坐标、原地改写与擦除测试交叉检查。

这些性质可从转移语义归纳推导，测试用于发现实现偏差；测试成功本身不能替代对任意运行的归纳证明。

## 4. 四个核心实验和实际结果

### A. 无限交替输出的有限前缀

两条规则为：

| 当前状态 | 读符号 | 写符号 | 移动 | 下一状态 | 输出 |
|---|---|---|---|---|---|
| a | _ | 0 | +1 | b | 0 |
| b | _ | 1 | +1 | a | 1 |

实际运行6步得到 `010101`。由规则可另外归纳：每次访问新的空白格，h_t=t，状态按奇偶切换，因此每一步都输出且永远有下一步。无限输出的结论来自这个归纳，不是来自6步日志。

对齐原例布局的四阶段版本每隔一步打印一个位：p0 打印0并右移；gap0 只右移；p1 打印1并右移；gap1 只右移。实际12步输出同样的 `010101`，工作带非空白位置为0、2、4、6、8、10。

### B. 不停机而只输出一次

first 状态在空白格写0、输出0、右移并转入 silent。silent 在空白格不输出，只右移并保持 silent。

实际12步只输出 `0`。更强的结论可由规则证明：第一步后 h_t=t，读头前方仍为空白，每一步继续右移而不输出。因此机器永远执行，但总共仅输出一个结果位。按这里保留的输出判据，它是 circular。

### C. 超过观察上限才开始输出

`delayed_forever(T)` 用 T 个等待状态和一个输出状态，先执行 T 次无输出右移，再每步输出0。T 是构造机器时给定的有限非负整数，不是“等到无穷”的状态。

对任意有限 T，该机器描述有限。等待链逐步展开后，首次输出发生在 T+1 步，运行 n 步得到的结果位数恰为 max(0,n−T)。

实际 T=20：

- 上限20：输出为空，状态仍可转移。
- 上限24：输出 `0000`，第一位在第21步出现。
- 永远无输出的对照机在前20步也给出相同的空输出历史。

这两台机器的控制状态和描述可以不同；这里说“相同”只针对观察到的输出历史，不是声称完整配置相同。这个参数化构造足以反驳“固定超时前未输出，所以永不输出”的推断。它没有排除读取并分析具体规则的正确证明方法，也不独自构成全部不可判定性的证明。

### D. 有限穷举的边界

固定 Q={q}、Γ={_,x}，每个表项可选2种写符号、3种移动、3种输出，共18个动作。两个输入表项全部指定，故恰有18²=324张表。枚举的是所有这种受限现代转导器的总转移表，不是所有图灵机。

实际对每台执行20步：

| 20步后观察到的输出长度 | 表的数量 |
|---:|---:|
| 0 | 96 |
| 1 | 2 |
| 10 | 20 |
| 19 | 2 |
| 20 | 204 |
| 合计 | 324 |

324台均报告 `cap_reached`；本有限类的表都是总的，所以由模型结构可另知它们不会因缺失规则停止。程序没有将输出长短转成 circle-free 标签。穷举覆盖的是规定的324张表；更大状态集、其他字母表、部分转移表等均不在范围内。即使对某个受限类有完整决策程序，也不能外推到任意程序。

## 5. 运行方法与验证记录

工作目录应为本 README 所在目录。准确命令：

```sh
python3 --version
```

实际环境：CPython 3.12.14，Linux x86_64，glibc 2.41。详细版本保存在 `results.json` 的 environment 字段。运行日志的测试耗时会随机器变化；测试逻辑、机器轨迹和枚举计数应相同。

实际结果：15个测试全部通过。覆盖精确预期轨迹、原例间隔布局、有限输出但持续移动、延迟边界、T=0到100的超时反例、缺失规则、恰在上限停止、负坐标、原地动作、擦除、非法规则、重复运行一致性、324个枚举表的数量与唯一性、有限轨迹不变量。测试覆盖有限用例，不声称形式验证、穷尽程序正确性证明或历史规则表全量复现。

## 6. 文件与阅读顺序

- `simulator.py`：约150行以内的模型、执行器与机器构造。
- `test_simulator.py`：15项可重复测试与明确预期值。
- `run_examples.py`：生成全部原始运行证据。
- `results.json`：实际生成的完整逐步轨迹、环境和枚举结果。
- `tests.log`：实际测试输出，保留每项测试名。
- `make_report.py`：从 JSON 生成可读状态表与小结。
- `trace_tables.zh-CN.md`：供文章插入或逐格核对的状态表。
- `commands.log`：执行命令与返回码。
- `SHA256SUMS`：交付文件校验值；排除自身及自动生成的缓存。

阅读建议：先手算 A 的前两步，再对照状态表，然后运行测试，最后修改等待长度，检查首次输出是否仍在 T+1 步。不要把代码的 `cap_reached` 改名为“不可判定”或“不停机”：那会把资源限制误当成数学结论。
