# 手算与实跑导览

先读[模型契约与一般证明](MODEL.zh-CN.md)。以下所有数值均是教学输入，不是从史料、儿童实验或植物观测中估计的参数。完整结构化输出在[results.json](results/results.json)。

## 第一步：列出8个个体

每行依次写“标识：果类；遮阴任务输出”。果类为none者的采收输出设为skip，其余设为collect。

```text
a1: apple; skip
a2: apple; use
p1: pear; use
c1: cherry; skip
h1: peach; skip
o1: none; use
s1: none; skip
g1: none; skip
```

这些fruit_kind与shade_ready都是人为提供的属性报告；任务输出又事先按示例规定填写。这里没有分类器从照片或语言中识别果类。每行还有一个高度和visible_green=true，见[fixtures.py](fixtures.py)。

## 第二步：从一个名称到过度泛化

脚本先记录a1第一次被叫tree，然后模拟把tree也用于剩下7个对象。这只是为了展示名称使用范围的变化，**不是从单样本自动学习相似性，也不是推断儿童实际会按此时间顺序行动**。

当没有指定任何区分需要时，所有对象一个块就够：

```text
{a1, a2, c1, g1, h1, o1, p1, s1}
```

若现在要求决定采收/略过，这一块就不再充分：同块内a1需collect，g1需skip。从“同名”不能得到一个对全块都正确的共同动作。

它叫“过度泛化”，是因为相对于此项需要省掉了有用区分；模型没有独立的“绝对正确树类外延”让程序去匹配。

## 第三步：需要带来的细分

### 只要采收/略过：2类

```text
collect: {a1, a2, c1, h1, p1}
skip:    {g1, o1, s1}
```

这两类内部任务输出相同，故充分。若只剩一个类，两种不同输出必被混在一起，因此不能再合并。

### 再要按果类分拣：5类

```text
apple:  {a1, a2}
cherry: {c1}
none:   {g1, o1, s1}
peach:  {h1}
pear:   {p1}
```

这里按sort_fruit输出重算。它也足以决定harvest，因为示例中none恰好对应skip，其余果类对应collect。所以新增采收任务不会把这5类再细分，体现“需要增加不保证严格变细”。

### 果类分拣加遮阴：7类

```text
(apple, skip):  {a1}
(apple, use):   {a2}
(cherry, skip): {c1}
(none, skip):   {g1, s1}
(none, use):    {o1}
(peach, skip):  {h1}
(pear, use):    {p1}
```

a1与a2虽然果类相同，遮阴输出不同，必须分开；g1与s1两项输出都相同，可以继续共类。这正是“果类分区”和“遮阴分区”的共同细化。

## 第四步：逐个体命名不是当前任务的必要条件

给每个对象独立一类，共8类，也足以决定这两项任务。但g1与s1仍是同样的(none, skip)，所以把它们分开对当前任务没有新增决策价值。

“8类比7类多”是确定的；“因此某个人记忆更差”没有被实验。模型没有心理成本曲线。

撤回遮阴需要后，a1/a2可以重新合并，g1/o1/s1也可以重新合并，恢复5类。保留7类也仍然充分；只是它不再最粗。

## 第五步：为什么知道有两类还不够

现在限制观察者只能看到visible_green。8个对象全是true，因此它只得到一个观测类。正确采收输出却有5个collect与3个skip，形成15对冲突：

```text
5 × 3 = 15
第一个按标识排序的冲突见证：a1 与 g1
观测：同为绿色
任务：a1 collect；g1 skip
```

任何只输入“绿色”的确定规则，对这两个对象只能报同一个结果，所以不能两者都正确。改用fruit_kind观测后，示例定义使采收输出可由果类确定，冲突归零。

这显示新增什么证据才能解决本例；不证明现实里看见果实就总能决定采收，也没有给新对象作泛化保证。

## 第六步：边界对象用上位词

另造6个对象，按人为约定输出：

```text
b1 height=3    → shrub
b2 height=4    → plant
b3 height=5    → plant
b4 height=6    → plant
b5 height=7    → tree
b6 height=null → plant
```

区间端点4与6包含在中间带中。null是未知高度，和已知中间值不同。所有对象当前陈列动作都是keep，所以统一报告plant也不影响该任务的输出。

特别注意：这里产生的3个组是**报告标签组**。plant作为上位概念包含全部6个对象，包括报shrub的b1和报tree的b5。不能把“这次被报plant的4个对象”误读为“植物一词的完整外延”。模型展示可选择的命名层级，并未把属/种层级全部压成互斥自然类别。

如果任务改为按对象选择不同搬运方式，统一用plant可能不再充分。测试明确检查这个反例。因此“别争树还是灌木”不能无条件扩展成“永远不需要细分”。

## 第七步：未知与部分准确

未知值演示：

```text
observed=True  → Truth.TRUE
observed=False → Truth.FALSE
observed=None  → Truth.UNKNOWN
```

这只是三种证据状态，没有逻辑连接词的演算。`bool(Truth.UNKNOWN)`会抛TypeError，要求调用者明确处理未知。两个对象都缺测，不保证它们都“不具备”该性质；代码另造一对缺测相同而正确任务不同的对象作为反例。

准确性演示的有限参照是：

```text
visible_green=True, height=5.0, fruit_kind=none
```

只说visible_green=True：准确，但没有覆盖全部3个参照字段。再声称height=7.0：反而不准确。即使所有3字段都说对，也只穷尽了这张小表，不是对象的全部性质。

## 第八步：读懂验证文件

[tests.log](results/tests.log)记录真实测试名和运行结果。测试包括：

- 8对象示例的类数、分区细化与15对冲突。
- 在0–5对象上枚举全部二值任务和全部分区，共1955例，检查充分性当且仅当细化理想任务分区。
- 在4对象上对三值任务及全部分区检查1215例。
- 在4对象上检查两项二值任务全部256组组合的共同细化恒等式。
- 15种观测分区与16种二值目标组合，共240例，检查冲突为空当且仅当观测足以识别目标。
- 空域、重复ID、分区重叠、缺字段、未定目标、非有限数值、True与1混同、阈值端点、未知转布尔、部分断言等边界。
- 修改结果字典后，摘要必须反映真实字段，不能保留写死的成功文字。

[determinism.json](results/determinism.json)比较两个独立进程、两个PYTHONHASHSEED下的结果文件哈希，以及它们与交付结果的一致性。测试穷举数量、实际测试方法数、运行时长是不同概念；方法数和时间以实跑日志为准。
