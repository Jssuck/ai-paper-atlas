## 发现、交作者修复、再核验

以下问题在作者冻结前或第一轮冻结审计中发现；均由作者修改主体，本审计没有代改实现。

1. **摘要把计算结论写死。** 修改结果字典中的共同细化、冲突数、陈列充分性、未知及准确/完整字段后，旧摘要仍输出原来的 True、0、False。最终摘要全部读取实际字段。审计主动注入相反结果，确认六处报告都改变，见 [injected-summary.txt](injected-summary.txt)。这是报告故障注入，不是实际模型产生相反结论。
2. **一次性生成器被验证过程耗尽。** 旧版向 `task_partition` 传入含两个对象的生成器会静默得到空分区。最终明确要求可重遍历的 `Sequence[Item]`，拒绝生成器；非 Item、非 Mapping 的输入也以 ValueError 拒绝。
3. **巨大有限整数溢出。** `boundary_name(10**500)` 及巨大整数阈值曾因 `math.isfinite` 隐式转浮点而抛 OverflowError。最终整数直接按有限整数处理，两个探针均通过。
4. **事实核验的未知语义与键契约不清。** 最终字段键须为非空字符串；参照与断言均为 None 不构成事实核验成功。文档明确 False 表示没有核验通过，不必然表示已证明反命题。已独立核验。
5. **字符串子类引起校验不一致。** 第一冻结版允许 `str` 子类通过 `validate_items` 和 `is_sufficient`，但 `task_partition` 拒绝。最终任务输出限定为非空内置 str，三个入口一致拒绝子类；新增作者回归后由47项变为48项测试。本报告仅以48项最终版本为准。

对于 `normalize_partition(None)`、块为整数、needs 为 None 等声明类型外输入，最终文档允许 Python TypeError；审计实际观察到三个 TypeError。**不声称所有任意坏对象都会抛同一种异常。**

## 独立 oracle，而非实现之间互相证明

公开脚本为 [audit.py](audit.py)，只使用标准库，未导入作者测试辅助函数。

- **分区枚举方式独立。** 使用 restricted-growth words，区别于作者从已有块递归插入的枚举器。
- **细化与共同细化的 oracle。** 把分区转成“对象对是否同类”的关系，直接以关系包含和关系交集检查全部4对象分区的225种配对。没有调用作者的细化函数来算期望结果。
- **任务充分性与最粗性。** 覆盖4对象上每项任务的全部15种相等模式，两项任务共225种组合。对每组逐一检查15个候选分区，共3375次直接比较类内目标向量，并由独立有效候选表找出唯一类数最小者。检查实现分区与该唯一候选一致。这里覆盖的是任务值重命名后的相等模式，不冒称枚举所有可能的字符串。
- **观测可识别性。** 对3对象的5种观测相等模式与64种二元双任务输出组合，共320种情形，独立枚举所有可能的确定决策表 h。比较“存在全对的 h”、直接对象对冲突和实际冲突见证三者。观测值包含 None、True、1，以检查缺测与类型敏感性。
- **接口与边界。** 44个应拒绝的输入调用，另有上述3个声明类型外探针；空域、无需要、重复需要、输入顺序、需求增加/撤回、阈值两端、超大整数、三种证据状态、未知转布尔、部分准确、有限覆盖及更换任务后不再充分均有检查。
- **交付示例。** 从结果中的8个对象表直接计算目标相等关系，核对各阶段分区、1/2/5/7/8/5类、每对象独立阶段、绿色观测的15对冲突与首个见证。不是仅比较一次作者运行与另一次作者运行。

这些有限检查用于发现实现错误，不代替一般证明，也不把不同检查的数量相加包装成统计置信度。

## 有意义的故障注入

对 `model.py` 的内存副本作精确源码替换；未修改交付文件。八个变异均被独立检查捕获，详细替换、检测函数与失败原因见 [mutations.json](mutations.json)：

1. 丢弃第二项任务
2. 把“所有块充分”改为“任一块充分”
3. 隐藏所有观测冲突
4. 合并 True 与 1 等标量类型
5. 把 UNKNOWN 改为 FALSE
6. 允许证据状态隐式转布尔
7. 错把下阈值端点纳入 shrub
8. 允许重复对象 ID 通过校验器

另外检查两个不同层次的故障：修改结果字典后摘要必须随之变化；在一次性完整包中增加必失败测试后，runner 必须非零退出、报告 failed，且不继续生成实验结果。后者的退出码为1，见 [injected-test-failure.log](injected-test-failure.log)。该日志中的失败是有意注入，不能误读为最终包测试失败。

### 审计自身的一次覆盖缺口

初次变异检查中，第8个变异存活：当时审计只从 `task_partition` 间接测试重复 ID，而其后的分区规范化器也会拒绝重复，因此校验器损坏被后续防线掩盖。审计增加直接调用 `validate_items` 的探针后捕获该错误。

保留 [harness-initial-attempt.log](harness-initial-attempt.log) 和 [mutations-before-harness-refinement.json](mutations-before-harness-refinement.json)，不把首次失败删掉或说成通过。首次47测试版本的通过记录在 [history/first-frozen-pass](history/first-frozen-pass/)，已被最终48测试版本取代，不用于最终字节的认证。此处只是审计自身覆盖补强，并非发现最终主体又存在重复 ID 漏洞。

## 数学前提审阅

一般结论成立所需条件在文档中已区分：固定有限论域；需要对应全域已知、确定的任务输出；同一组输入在调用中不变；按严格目标向量相等形成等价类；任意合法分区均可作为分类；每项任务要求零误差。

在这些条件下，每个充分块只能处在一个目标等价类中，故充分当且仅当细化任务等价类分区。这给出唯一最粗充分分区；有限情形下也给出唯一类数最小充分分区。它不优化程序长度、观察成本、决策树深度或人的记忆负担。

合并需要对应相等关系的交集，所以只可能变细或不变；撤回需要是重新计算，允许合并，不是不可逆学习定律。观测不可识别性只要求找到一对同观测却异任务输出的对象。最终证明把 h 的定义域明确为实际观测像集 O(X)，不对未见观测值作保证。

空域与非空无需要的情况分开：前者空分区，后者一个块。未知观测不等于假；None 相等仅意味着报告同样缺测。准确性核验、有限字段覆盖与任务充分性是三个不同检查。树/灌木/植物示例的互斥分组是本次报告标签，不能当作三者完整概念外延的互斥划分。

- 时间、临时目录、环境记录及执行日志字节可变；不属于结果确定性的字节一致性承诺。
- 八个变异全部检出只证明这些具体故障可检出，不是完备的变异覆盖率或“没有任何错误”的证明。
- 没有联网、安装软件、调用付费服务、训练模型或收集经验数据。没有把史料中的讨论当作现代算法、三值逻辑演算或心理学实验证实。
- 本审计审阅本附件的数学与代码边界；原书逐页转写、翻译与历史出处核实另有独立史料审阅，不由这些程序测试替代。
