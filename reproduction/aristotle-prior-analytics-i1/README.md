# 《前分析篇》I.1 的最小教学模型

对应阅读范围：I.1，24a10–24b30。此目录是配套教学代码，不是声称从原文复原出的“亚里士多德算法”。它把几个容易混淆的问题拆开：命题在一个解释中为真、结论是否为前提的语义后承、给定推导是否只用了已声明前提，以及原文对推论、证明和完善性的要求。

代码只用 Python 标准库，要求 Python 3.10 或以上。不安装依赖，不联网，不读取密钥，不写远端。所有文件均在本目录内。

## 快速运行

在终端进入本目录后：

```sh
python3 -B demo.py
python3 -B -m unittest -v test_model
python3 -B verify.py
```

`demo.py` 输出确定性的 JSON。`verify.py` 真正启动普通、`-O`、`-OO` 三种解释器模式，运行同一套测试，再逐字节比较三份演示输出。成功时更新 `report.json`；无论成功与否，都会保存当次 `verification.txt`。日志包含环境、完整命令、退出码与测试输出。运行时长会变化，报告内容不依赖时间。

如需手动逐项复核：

```sh
python3 -B -m unittest -v test_model
python3 -O -B -m unittest -v test_model
python3 -OO -B -m unittest -v test_model
python3 -B demo.py > report.json
```

## 语义契约：先读这些假设

1. 只有 1–3 个具名的一元项，例如 `("S", "M", "P")`。
2. 论域一定非空；单个项的外延默认允许为空。论域非空不等于所有项都非空。
3. `Prop(kind, subject, predicate)` 使用固定顺序：主项在前，谓项在后。
4. 本代码的 A、E、I、O 分别解释为：
   - A(S,P)：每一个 S 都是 P，即 S ⊆ P
   - E(S,P)：没有 S 是 P，即 S ∩ P = ∅
   - I(S,P)：有一个 S 是 P，即 S ∩ P ≠ ∅
   - O(S,P)：有一个 S 不是 P，即 S \ P ≠ ∅
5. `Language(terms, required_nonempty=frozenset())` 可显式限定若干项非空。这是对可接受模型增加的语义政策，不是程序悄悄加入的前提，不是对古代存在预设争论的裁决。
6. 不处理不定量陈述、模态、关系、多重量词、对象个数、等同关系或自然语言歧义。它只是一组用于对照阅读定义的现代外延解释。

### 支持集与有限枚举

有 k 个项时，一个对象可有 2^k 种成员资格真值类型。用整数的第 i 位表示对象是否属于第 i 个项。`Model(terms, support)` 保存实际出现的类型；每种出现的类型放一个代表。`support` 必须是非空、升序、无重复的整数元组。

两项有 4 种类型，非空支持集共 2^4−1 = 15 个；三项有 8 种类型，非空支持集共 2^8−1 = 255 个。一项则有 3 个。数字表示“类型支持集”，不是现实世界数，也不是所有带标签论域的数量。要求某项非空会进一步筛掉一些支持集。

例如 `Model(("S", "P"), (0,))` 含一个既不属于 S 也不属于 P 的代表对象：论域非空，两个项均为空。`Model(("S", "M", "P"), (3,))` 含一个属于 S、M 而不属于 P 的代表对象。

程序穷举这些支持集。把同类型对象压缩为一个代表为何保留该片段的真值，以及它如何覆盖任意非空论域，是需要论证的数学理由；请结合主文的四类型／八类型压缩论证阅读。测试中的有限核验本身不能替代一般证明。

## 正式 API

```python
from logic import Language, Model, Prop, entails, enumerate_models, evaluate

language = Language(("S", "M", "P"))
premises = (Prop("A", "S", "M"), Prop("A", "M", "P"))
conclusion = Prop("A", "S", "P")
result = entails(language, premises, conclusion)
print(result.holds)                       # True
print(result.satisfying_premise_models)   # 15
print(result.admissible_models)           # 255
print(result.countermodel)                # None
```

- `evaluate(prop, model)`：单个模型中的真值。
- `enumerate_models(language)`：按支持集掩码的整数值递增，返回所有符合政策的支持集模型。掩码从 1 到 `2**(2**k)-1`；其第 t 位为 1 表示真值类型 t 出现。
- `entails(language, premises, conclusion)`：检查所有“前提全真”的可接受模型是否也使结论真，返回 `Entailment`。
- `countermodel`：若后承失败，返回上述顺序中实际使前提全真、结论假的首个模型；演示会把各个真值写入报告。这保证可复现，不保证代表对象数最少，也不保证某种“最自然”反例或最小见证。
- `satisfying_premise_models == 0`：没有支持集同时满足前提。此时经典语义后承仍返回真；这是空泛成立，不能被表述成“已找到一组真实证明前提”。

命题、语言、模型、证书步骤均为冻结数据类。项必须显式声明；元组／冻结集合类型、整数范围、重复项等都会检查。布尔值不会被当成索引或类型编号。公开检查入口会重新验证这些对象，拒绝以 `object.__setattr__` 改坏的字段或以 `object.__new__` 制造的不完整实例。冻结数据类避免普通的意外修改，并非防御同进程恶意代码的安全沙箱。生产代码不依赖会被 `-O` 去掉的 `assert`。

## 证书检查器到底检查什么

`Step(claim, rule, refs=(), assumption=None)` 描述一步。前提索引 `assumption` 与步骤索引 `refs` 都从 0 开始，但两者不是一回事。`check_certificate(language, premises, conclusion, steps)` 检查每一步，包括最终结果未使用的步骤。

规则仅有：

| 名称 | 输入 | 输出 |
|---|---|---|
| `assume` | 显式前提的索引 | 与该前提完全相同的命题 |
| `a_trans` | A(S,M), A(M,P) | A(S,P) |
| `e_sym` | E(S,P) | E(P,S) |
| `e_down` | A(S,M), E(M,P) | E(S,P) |
| `i_up` | I(S,M), A(M,P) | I(S,P) |
| `o_from_i_e` | I(S,M), E(M,P) | O(S,P) |

后一规则中的见证对象已经属于 S、M，而 E(M,P) 保证它不属于 P，因此产生 O(S,P)。程序不会凭空制造存在见证。

以上就是完整的实现子集：没有从 O 前提继续传播 O 的规则，也没有 I 换位规则。主文若讨论更广的正确变形，并不表示本证书检查器已全部实现；语义枚举仍可另行检查相应命题。

引用必须严格指向先前步骤。导入未声明前提、把 A 的方向倒过来、用错误规则类型、跳过最终结论检查等都会报 `ValidationError`。这表示输入或证书不符合契约，不等同于已经证明目标论证在语义上无效。

返回值记录 `used_assumptions`、`unused_assumptions`、`repeats_assumption` 和步数。前提“被语法引用”不等于它在逻辑上不可删去，更不等于已经穷尽原文“通过这些”的含义。重复前提的不同索引也分别记录。

此检查器没有搜索证明，没有“所有有效式都可证明”的完备性承诺，也没有使用非空政策的额外推导规则。比如语义政策 S≠∅ 可使 A(S,P) 后承 I(S,P)，但本证书规则集故意没有相应的存在引入规则。

## 五件不能混成一件的事

1. 一个特定模型中，某句话真不真。
2. 该形式是否语义有效，即有没有前提全真、结论假的可接受反例。
3. 这个具体证书有没有偷偷借用前提，以及最后一步依赖哪些已声明前提。
4. 结论是否有别于所置前提；程序只能报告是否字面上重复。
5. 原文有关“真正通过这些”、证明前提的真理与来源、完善／不完善推论的要求。

程序处理前三项的一部分，并给第四项一个窄提示；它不裁定第五项。通过 `e_sym` 后接受的证书，不因此自动被程序标成古代意义上的“不完善”；直接用 `a_trans` 得到结论，也不自动取得“完善证明”的历史标签。

## 测试覆盖与证据边界

作者使用独立写法的直接量词判定器：用布尔元组生成对象，以 `all` / `any` 直接解释命题，而不是复用生产实现的整数位运算。它仍由本代码作者编写，不能称为独立审计。

实际测试包括：

- 所有 1–3 项支持集及所有指定项非空政策，交叉核对枚举
- 9,432 个“命题 × 支持集”真值对照，含主项、谓项相同的情况
- 1–2 项所有单前提／结论组合，在全部非空政策下对照完整 `entails`
- 3 项的 23,976 个双前提／结论组合，以预先缓存的真值集合核对后承关系；这部分不是调用 23,976 次完整 `entails`
- 3 项在全部 8 种非空政策下，共 1,152 个确定性双前提样本，运行完整 `entails` 并核对计数及反模型
- 117 个规则实例及所有 255 个三项支持集上的作者核验
- 三项全部命题／支持集组合中的 I、O 见证记录，检查见证确实属于／不属于相应外延
- 输入类型、非法引用、未声明前提、未使用坏步骤、错误逆向、假前提与真结论误判等边界情况
- 普通、`-O`、`-OO` 模式运行同一测试，并逐字节比较演示报告

这些是可重跑的有限检查。它们并未证明软件没有其他缺陷，也不能单独建立关于任意语言或亚里士多德整体逻辑体系的结论。
