# I.1 教学模型独立代码审计

## 结论与范围

**修复后通过本次有界独立审计，无未解决的代码阻断项。** 审计对象是现代的一元 A/E/I/O 集合语义、非空政策、有限支持枚举与小型推导证书；没有把程序视为亚里士多德原有算法，也没有由有限测试推出任意软件或历史解释均正确。

本审计逐一阅读 `logic.py`、`proofs.py`、`demo.py`、`test_model.py`、`verify.py`、README、走查，以及主文全文。独立检查代码位于 `independent-review/`，由审计者另写，没有导入作者测试模块或其 oracle，没有调用生产私有求值／推导辅助函数充当答案。作者的 26 项测试与本次独立检查分别记录，不能合并为“独立作者测试”。

最终文件及证据的 SHA-256 和字节数见 [code-audit.json](code-audit.json)。其中正文、代码、文档、报告、作者日志与独立审计脚本／日志分别绑定；任何被绑定文件变化后，需重新核验相应部分。JSON 不给自身做循环哈希。

## 实际发现并修复的问题

首轮发现：冻结数据类并非输入验证的充分保证。通过 `object.__setattr__` 绕过普通构造后，将 `Step.assumption` 改为 `-1`，旧版证书入口会接受 Python 的负索引，并报告 `used_assumptions=(-1,)`；布尔索引和 `assume` 上的非法引用也可漏检。首轮真实失败保留于 `independent-review/initial-probe.log`，它不是最终版本的失败记录。

审计者未直接修改生产代码。作者随后在公开入口重新核验精确类型和字段，补上缺字段实例的 `ValidationError` 转换，证书逐步重验 `Step` 及命题。独立复测覆盖负数／布尔索引、篡改规则／引用、篡改命题／语言／支持和 `object.__new__` 不完整对象；最终三个解释器模式均拒绝这些输入。

这是 API 健壮性修复，不构成抵御能够改写同进程函数或类的恶意代码的安全沙箱保证。README 已明确这个边界。

另核对并澄清了文档路径、支持掩码顺序与最小反模型的区别。程序按支持掩码的整数值递增，返回该顺序中的第一个反模型，**不保证对象数最小**。主文的手算对象编号与程序的真值类型编号分别展示，不混用两个不同例子的前提真值。

## 独立方法与实际覆盖

主要 oracle 直接使用集合包含、不相交、交集和差集；它与生产实现中的位运算判断分开。标记论域部分先任取各项的集合外延，再压缩成员类型，保留重复类型对象供交叉比较；不是从生产枚举器抄出预期结果。

以下计数为**每一种解释器模式**真正执行的结果，不是把三次重复运行加总后伪装成更广覆盖：

| 检查 | 实际范围／数量 |
|---|---|
| 支持与非空政策 | 1、2、3 项共 14 种政策；2,106 次可接受性核对 |
| 支持上的真假 | 全部 3、15、255 个支持与所有含同主谓项的命题，共 9,432 对 |
| 有标签模型 | 1–3 项、论域大小 1–4 的全部外延组合，共 5,050 个模型、174,040 次真假对照 |
| 完整后承入口 | 34,740 次真实 `entails` 调用，每次比较后承、两个模型计数和首个反模型 |
| 规则接受／拒绝 | 187,920 个规则、输入命题、输出命题组合，完整核验方向、量质与结论 |
| 有效规则实例的语义 | 117 个实例逐一检查全部 255 个三项支持，共 29,835 次 |
| 非法输入 | 76 项拒绝检查，包含错误异常类型亦算失败 |
| 依赖图 | 两个另造的乱序索引／重复前提／无关步骤例子，逐项核对最终祖先依赖 |

34,740 次完整后承调用具体包括：

- 1–2 项在所有非空政策下的全部无序、允许重复的双前提组合与所有结论，合计 8,784 次。
- 3 项默认允许空项时，全部 666 个无序双前提组合与 36 个结论，合计 23,976 次；这里确实逐次调用完整生产入口，不仅比较预存真值集合。
- 3 项其余 7 种非空政策，各检查 180 个确定性双前提样本，合计 1,260 次。这一部分是抽样，未声称穷尽所有问题。
- 14 种政策下的空前提与重复自前提检查，共 720 次。

独立 oracle 为效率缓存其直接集合真值，但生产 `entails` 未被替换、缓存或打补丁。返回的 18,981 个反模型都重新核对有效性、词表、政策和声明的遍历顺序。

规则网格包括 `e_sym` 及四个二输入规则的全部 36 种命题输入与全部 36 种输出；由此也检查错误换位、错误种类和错误中项。依赖与非法证书检查另外覆盖先前引用、自引用／未来引用、非法末步、未经声明／偷换的前提、未使用却非法的步骤、重复前提的不同索引及精确语言顺序。依赖记录只是语法使用，不等于逻辑不可删除性。

## 三种模式、确定性与输出核验

实际运行环境：Python 3.12.14，Linux x86_64，标准库。没有安装、密钥、付费步骤或远端写入。声明最低 Python 3.10，但本审计未另外运行 3.10 或其他操作系统。

`independent-review/run_review.py` 在普通、`-O`、`-OO` 三种模式运行同一套独立检查。三者全部退出 0，计数一致。检查使用显式异常而非可被优化删除的 `assert`。执行前后对生产文件和独立检查脚本取哈希，确认运行时源文件未变。

随后在三个模式中分别使用 `PYTHONHASHSEED=0/141/271828`，九次 `demo.py` 输出逐字节相同，并与保存的 `report.json` 相同。报告为 11,266 字节，SHA-256：

`4681fd8cabc61dcd613f6bd0ec3af4128110501e469916289e3214edd7f481b4`

`report_checks.py` 不导入任何生产模块，另从 JSON 重建集合：核对 8 个论证报告、8 处模型描述、2 个原始对象与类型编号映射例子，以及 4 个存在见证。每个报告的后承、可接受模型数、满足前提数、反模型及所列真值均一致。

## 变异检验

`mutation_checks.py` 仅在临时目录复制并改动代码，运行完删除临时副本；原生产文件前后哈希一致。12 个刻意错误均被独立检查识别，且不是语法错误或无法导入造成的假“检出”：

1. A、E、I、O 各自反转真假，共 4 个。
2. 忽略项非空政策。
3. 枚举漏掉首个支持。
4. E 换项错为原方向。
5. I 传播输出错为 O。
6. I 与 E 的规则输出错为 I。
7. 允许假设节点偷换已声明前提。
8. 把全部前提都记为最终依赖。
9. 不检查末步是否为请求结论。

确切替换文本、变异副本哈希、退出码和触发的独立检查见 `independent-review/mutation-results.json`；各失败日志单独保存。12/12 只表示这 12 种已选错误可被检测，不是全面变异覆盖或软件正确性证明。

## 可复跑入口与证据

在本目录运行：

```sh
python3 -B independent-review/run_review.py
python3 -B independent-review/report_checks.py
python3 -B independent-review/mutation_checks.py
```

- `normal.log`、`O.log`、`OO.log`：三个模式的命令、开始时间、完整检查阶段、计数与退出码。
- `run-results.json`：环境、运行前后源哈希、三个模式、九次报告的哈希及比较结果。
- `demo-*-seed*.json`：九份真实输出。
- `report-validation.log`：独立 JSON／集合核验结果。
- `mutation-results.json`、`mutant-*.log`：变异核验结果。
- `initial-probe.log`：修复前发现记录；最终源码绑定对应修复后版本。
- `verification.txt`：作者实际运行的 26 项测试及三模式日志，保持作者证据身份。

重新运行会产生新的时间日志，因此原 `code-audit.json` 的证据哈希将失配；应先保留原证据，重跑后重新封存，不能把旧哈希当成新日志的证明。

## 明确未证明的事项

有限测试不替代主文关于任意非空论域的成员类型压缩证明；该一般结论依赖限定语言只问一元成员关系与有无见证。计数、二元关系、对象身份、时间和模态不在其内。证书规则可靠性检查也不表示其完备，没有自动搜证书或读取非空政策引入存在句的实现。

审计不认证自然语言事实、词义稳定、原作者对存在承诺的最终立场、科学知识资格或完善／不完善的历史分类。它只支持冻结文件所声明的现代教学片段及上述实际检查结果。
