# II.18 教学复现：指定链中的最近理由，不是从集合自动发现原因

这是《后分析篇》II.18（99b9–14）的**现代教学重构**，不是古代程序的复原，也不是现实因果识别工具。原章的原因资格不能由这些有限集合测试认证。主体D、近中项C、较远中项B、目标性质A沿给定链排列；古代字母的Γ在程序中记作C。

## 怎样运行

只需 Python 3.10 或以上与标准库，无第三方依赖。在本目录执行：

```sh
python run_all.py
```

它实际运行普通、`-O`、`-OO` 三种模式下的全部单元测试，再运行演示和Notebook代码。输出保存到 `logs/`；`environment.json` 记录环境与执行方式；`sha256.json` 记录文件校验值，不包括自身。新一次运行会更新日志和Notebook输出，运行时间可能不同。

也可逐项运行：

```sh
python -m unittest -v
python -O -m unittest -v
python -OO -m unittest -v
python model.py
python run_notebook.py
```

## 输入与检查的准确含义

- `ChainCertificate(('D','C','B','A'))` 是**显式选定的解释链结构**。项名须互异；这只是本教学模型的无环条件，不是断言一切现实说明都具有线性结构。
- `extensions` 为各项在一个有限论域上的集合；允许空集和相同外延。这里使用现代集合语义，不把它冒充亚里士多德的存在承担政策。
- `declared_edges` 为用户给定的相邻步骤。函数检查步骤是否声明、集合包含是否成立，但**不验证这些步骤在科学意义上直接、必要、适当或真正具有因果作用**。
- `nearest_declared_reason` 在有内部中项时取链的第二个名字。在仅有B→A时返回B；这是“以主体本身为端点”的约定，不增添B→B边，不证明B造成自身，也不证明B→A确实不可再分。
- `finite_middle_candidates` 只检查主体包含于中项、中项包含于目标。它既不能排序原因，也不排除空项导致的空真。
- `nearest_choices` 只汇总所提供的同一问题的结构证书，调用前另用`validate`核实有限真值。空输入只表示没有提供证书，不表示不存在说明；多个名字不自动表示不同现实机制。
- `transitive_closure` 给的是推导可达性。闭包新添D→A不是原始直接说明；若把它当作直接边输入，程序虽可接受其外延，却会丢失中项信息。

## 一般证明与有限实验的分工

设任意论域上的有限链为X₀⊆X₁⊆…⊆Xₙ，n≥1。任取x∈X₀，由第一个包含关系得x∈X₁，逐步应用相邻包含关系，最终得到x∈Xₙ。因此X₀⊆Xₙ。这是对任意对象、任意有限链成立的推导，不依赖本程序枚举。

若n≥2，每个内部Xᵢ都满足X₀⊆Xᵢ⊆Xₙ，因此可能有多个形式有效中项。指定链中的第一个内部名字是X₁，但这只是链次序的事实，**不是仅从端点外延推出的原因定理**。例如C=B时，D→C→B→A与D→B→C→A同样符合外延包含，两个给定次序却返回不同最近名字。相同外延没有决定解释次序。

枚举令四个集合A/B/C/D各取3元素论域的任意子集：共有16³=4096个赋值。要满足D⊆C⊆B⊆A，每个元素有五种允许的成员模式：都不属于；仅属于A；属于A、B；属于A、B、C；属于全部四集。故链成立赋值应有5³=125个。D为空时去掉“属于全部四集”这一模式，得到4³=64个；D非空为125−64=61个。这个独立计数与程序结果一致。有限枚举是实现核验，不替代上面的任意论域证明，也不认证真实原因。

## 真实运行结果与反例

本次24项测试在普通、`-O`、`-OO`模式均通过，日志保存各次真实输出；无依赖会被优化模式移除的`assert`验收。`demo.log`给出：

- 对A属于D的问题，指定链返回C；对A属于C返回B；对A属于B返回B端点，无内部中项。
- C与B都可为D/A的有限外延中项，但不能因此把二者都叫最近。
- 另给D→E→B→A的证书，汇总最近名字为C、E，不强造唯一答案。
- 原始声明无D→A，传递闭包却有；将闭包当直接解释输入会产生D端点，这是混淆数据层次的后果。
- 4096个赋值中125个满足链，61个有非空D；链成立但传递结论失败的赋值为0。

测试还覆盖：缺少声明边、错误方向、端点为真而中间包含为假、重复项名循环、仅目标无解释、缺少集合、非集合数据、空主体、全空模型、同外延不同链序和混合问题。每种失败的含义均限定于这个API，而非现实世界的无原因判决。

## Notebook与可重现边界

[tutorial.ipynb](tutorial.ipynb) 含5个短Python代码单元，按“指定链→问题移动→外延与原因分离→分支/闭包陷阱→独立计数”顺序教学。实际由 [run_notebook.py](run_notebook.py) 用标准库`exec`顺序执行，保存输出；**没有使用Jupyter内核**。这能核验普通Python代码，不测试Jupyter特有魔法、扩展或完整交互界面。

Notebook采用nbformat 4.5结构、稳定cell ID与Python 3内核元数据，并检查结构和代码；无需安装新软件。读者可以在已有Jupyter环境打开后“Restart Kernel and Run All”作进一步界面核验。
