# Gödel 1931：三个可运行的 TOY 教学实验

这套原创小程序只帮助理解“符号 → 整数”“机械替换”“给定证明可检查”三个局部环节。它不是 Gödel 1931 年形式系统的复刻，也不是不完备性定理的计算机证明。

## 运行

需要 Python 3.10 或更新版本；脚本和测试只用标准库。先进入本目录：

```bash
python demo.py
python -m unittest -v
python execute_notebook_stdlib.py
```

- `godel_toy.py`：编码器、无量词语法与替换、独立的微型证明系统。
- `test_godel_toy.py`：45 项测试，包含 341 个小序列的穷举往返与无碰撞检查。
- `demo.py`：中文演示输出。
- `godel1931_toy.ipynb`：由浅入深的教学 notebook，包含已保存的实际运行输出。
- `execute_notebook_stdlib.py`：顺序执行本 notebook 的纯 Python 单元，并保存输出。
- `logs/`：本次执行记录和交付文件校验清单。

Notebook 可在已有 Python 内核的 Jupyter 中打开；本环境没有安装 Jupyter、nbclient 或 ipykernel。因此这里只实际验证了所有代码单元按顺序在同一 Python 命名空间执行，以及 JSON 基本结构；没有声称完成 Jupyter 内核或前端兼容性测试。它不使用 magic、交互控件或富显示，运行不依赖这些功能。

## 实验一：素数幂编码

我们约定：

```text
code([]) = 1
code([a₀, …, aₖ]) = 2^(a₀+1) × 3^(a₁+1) × … × pₖ^(aₖ+1)
code([0, 2, 1]) = 2^1 × 3^3 × 5^2 = 1350
```

这是刻意改过的 TOY 约定：指数为 `aᵢ+1`，使序列元素可以是 0，同时所有已占用位置的指数仍为正。不要把它和原文直接以正的符号代码作为指数的做法混用。空序列的代码 1 与单元素序列 `[0]` 的代码 2 不同。

唯一分解使编码可逆，但并非每个正整数都代表合法序列。`10 = 2×5` 缺了中间的位置素数 3，解码器明确拒绝它；不能把缺位误当成符号 0。组件读取采用从 0 开始的下标。拼接先解码、连接序列、重新编码；直接把两个代码相乘通常不是拼接。

为限制运行量，代码仅接受至多 24 个元素，每个元素为 0 至 31 的整数。它也拒绝 Python 的布尔值充当整数。这个有限边界服务于教学和可复现运行，与定理的适用条件无关。

## 实验二：在无量词语法树中替换数字项

小语言只有数字项、变量 `x/y/z`、加法、等式、否定与合取。没有全称/存在量词，没有绑定器。因此每个变量出现都是自由出现，我们才能安全地采用简洁递归替换，避免把含绑定变量的错误实现包装成通用算法。

```text
原式：x + 1 = 3
将 x 替换为数字项 2：2 + 1 = 3
原式前缀 tokens：(3, 2, 1, 0, 0, 1, 0, 3)
替换后 tokens：   (3, 2, 0, 2, 0, 1, 0, 3)
```

前缀标签的元数固定，故可无歧义读出结构；例如 `3` 是等式标签，`2` 是加法标签，`1,0` 表示变量 x，而 `0,2` 表示数字项 2。完整约定见函数 `formula_tokens` 的说明。AST 至多 12 个节点；数字项与环境赋值为 0 至 31。加法结果仍按普通自然数计算，不做模运算。

这里的 `Nat(2)` 是便于阅读的数字项节点，不是原文逐字展开的后继符号串；`substitute_numeral` 也不是原文完整的 `Sb` 实现。把替换前后两个有限对象都编码为整数，可以直观看见“语法操作也能成为关于数的操作”这一步的方向。

`evaluate` 返回自然数解释下的真假。它不是证明搜索，也不等于“某个形式理论证明了该句子”。这一区分不能省略。

## 实验三：检查给定证明，和搜索证明

这个实验另起一个独立的有限系统，和实验二的算术 AST 并未接成完整形式理论：

```text
原子命题代码：A=0，B=1，C=2，D=3
唯一公理：A
规则：A→B，B→C，C→D
一行证明：(命题代码, 理由代码, 前提行号)
理由 0 表示公理；1/2/3 对应上述三条规则
公理的前提行号必须为 0；推理引用的行号从 1 开始且必须早于当前行
```

有效示例为 `[(0,0,0), (1,1,1), (2,2,2)]`，即 A、由 A 得 B、由 B 得 C。把三元组摊平成序列再编码，得到 `p = 12324817146749777670`。`proof_relation(p, 2)` 返回 True：这个给定的证明对象以 C 结束。

检查器会拒绝假公理、未知规则、自我/未来引用、错误前提、错误结论与格式不对的代码。`encode_proof` 能给一个形式正确但推理无效的对象编号，这不代表它就成了证明；真正的验证发生在 `check_proof` 中。

搜索器按行数逐层枚举有效证明前缀，包含重复公理和对非相邻前提的引用。它返回的是有界搜索结果：

- C：至多 2 行，检查 3 个前缀，没有找到。
- C：至多 3 行，检查 9 个前缀，找到 A、B、C。

所以“这次没有找到”不能直接升级成“不可证明”。这个例子是对该错误推论的具体反例。我们的玩具系统只有四个原子和有限条规则，实际上可以用独立的有限闭包计算判定所有可导出的原子；它本身并不是展示不完备性所需的强算术理论。

## 什么被验证了，什么还没有

已运行的测试核验了这些程序在声明范围内的行为，包括边界与拒绝路径。测试不是所有自然数情形的数学证明。

这些代码没有证明语法/证明关系在某个算术理论中的可表示性，没有构造对角化固定点或 Gödel 句，没有建立一致性或 ω-一致性假设下的元数学推导，也没有实现第一或第二不完备性定理。尤其不能从 Python 函数“能运行”直接推出某关系具有原文所需的算术表达或可表示性。它们应配合原文精读，用来拆开概念，不代替定理证明。
