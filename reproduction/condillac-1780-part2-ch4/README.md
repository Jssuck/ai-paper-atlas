# Condillac《La Logique》II.IV：现代有限教学模型

这是原创教学程序，不是 Condillac 的算法复原，不是对真实语言起源或心理学的实验验证。历史参照使用 [1798 年印本正文 pp. 125–130](https://archive.org/download/b28772581_0022/b28772581_0022.pdf#page=133)；目录名中的 1780 用于标识作品。发布目录不包含原文扫描件或逐段翻译。

## 从这里开始

1. 阅读 [逐步手算](WALKTHROUGH.zh-CN.md)，先看经验损失与宇宙真值错误为何可能反向变化。
2. 阅读 [完整模型与一般证明](MODEL.zh-CN.md)，包括全部假设、最优残差、细化与双射改名。
3. 运行下列程序，对照真实输出。

## 环境与命令

仅依赖 Python 标准库，无需安装依赖、网络、账户或任何外部服务。语法要求 Python 3.10 或更新版本；实际验证环境是 CPython 3.12.14（完整系统信息见 [`evidence/verification.json`](evidence/verification.json)）。未声称测试了其他解释器版本。

在本目录运行：

```bash
python3 -B demo.py
python3 -B verify.py
python3 -B -O verify.py
python3 -B -OO verify.py
```

`-B` 只避免写入字节码缓存。`-O`、`-OO` 并非跳过验证的模式：三个命令都运行完整专门测试与相同穷举域。`-OO` 去除文档字符串也不影响程序。实现没有依赖可被优化删去的 Python `assert` 语句；输入校验与穷举检查使用显式异常，专门测试使用 `unittest` 的方法。

一次性重新产生当前解释器三种模式的验证和示例证据：

```bash
python3 -B record_evidence.py
```

该命令只写本目录 `evidence/`，依次启动当前 Python 解释器，记录 6 次运行的便携显示命令、退出码、日志散列及运行前后的源码／文档散列。命令中的解释器只显示文件名，实际执行选择当前 `sys.executable`；工作目录记录为相对的 `.`，不写入私有机器绝对路径。前后散列不一致时记录失败，防止把运行期间已修改的交付文件认证为相同版本。所有三种模式的示例输出还须逐字相同。它返回非零退出码时不能认定验证通过。直接查看当前交付的实际输出：

- [常规模式验证日志](evidence/verify-normal.txt)
- [-O 模式验证日志](evidence/verify-O.txt)
- [-OO 模式验证日志](evidence/verify-OO.txt)
- [常规示例输出](evidence/demo-normal.txt)、[-O 示例输出](evidence/demo-O.txt)、[-OO 示例输出](evidence/demo-OO.txt)
- [`evidence/verification.json`](evidence/verification.json)

日志中的 `unittest` 运行时间是当次实际记录，可随机器变化；没有把它当作性能基准。散列记录当次运行前后交付源码与文档的一致性；这不是对恶意中途修改再恢复的防篡改保证。修改这些文件后须重新运行，旧证据不能代表新版本。

## 文件与接口

| 文件 | 用途 |
| --- | --- |
| `finite_language.py` | 不可变有限问题定义；预测、两个误差、拟合、残差、改名、细化 |
| `examples.py` | 七组手算示例的原始数据与阶段 |
| `demo.py` | 逐行打印各示例的实际结果 |
| `test_finite_language.py` | 24 个专门测试方法，包括边界和无效输入 |
| `verify.py` | 专门测试及直接枚举参考值的小域穷举 |
| `record_evidence.py` | 在三种优化模式运行并保存证据 |
| `MODEL.zh-CN.md` | 定义、假设、一般证明与历史解释边界 |
| `WALKTHROUGH.zh-CN.md` | 每组示例的逐步计算 |

主文的对象集非空；程序额外测试空对象集这一边界扩展，仍要求标签集和答案集非空。“表示充分当且仅当真值在每个非空单元恒定”的证明见模型文档 §8，不是另一个已实现 API。

`Problem` 的 `objects, labels, answers` 分别枚举对象、标签、答案；`r, h, f` 分别依上述对应域的顺序排列；`counts` 按对象行、答案列排列。`fit` 返回新问题，不改原对象。答案正计数平局使用声明的答案顺序，整个标签无证据时保留旧解码。

`refine(problem, new_labels, new_r, parents)` 中，`parents` 按新标签顺序给出映回旧标签的函数。它必须满足每个对象细标签的父标签等于旧标签。函数先正确传递旧解码，因此只运行它不会改变预测；随后可另行运行 `fit`。

## 精确的穷举范围与计数

这些是限定域中的组合数，不是独立实验次数，也不应将它们相加包装成一个大型基准分数。

| 类别 | 枚举域 | 精确次数 |
| --- | --- | ---: |
| 多数拟合上下文 | 4 种表征 × 81 个观察矩阵 × 4 个旧解码器 | 1,296 |
| 多数参考候选损失计算 | 每个拟合上下文直接枚举 4 个候选解码器 | 5,184 |
| 真值变体 | 每个拟合上下文配 4 个真值函数 | 5,184 |
| 双射改名 | 每个拟合上下文配两个新名称的 2 种排列 | 2,592 |
| 细化上下文 | 4 种父映射 × 4 种细表征 × 81 个观察矩阵 | 1,296 |
| 细化参考候选损失计算 | 每个细化上下文分别枚举粗／细各 4 个解码器 | 10,368 |
| 解码传递 | 每个细化上下文配 4 个旧解码器 | 5,184 |
| 显式失败路径控制 | 假条件必须抛出指定校验异常 | 1 |

对象、标签、答案各有 2 个元素。观察矩阵有 4 个单元格，每格取 0、1、2，共 $`3^4=81`$ 个。父映射与细表征合成粗表征，故每个细化上下文都满足细化关系。没有要求表征满射；空标签和零记录被保留在枚举域中。

参考枚举直接按整数索引计算每个候选解码器的逐记录损失，取其最小值；不会用待测 `fit` 或标签聚合函数构造期望最优值。专门测试另覆盖空宇宙、一个答案、三个标签／答案、极大整数、非字典顺序平局、错误记录、未见对象退步、非法输入等。

没有开展变异测试或宣称变异覆盖率。显式失败路径控制仅确认验证器自己的假条件会触发异常，不是把导入失败、语法错误或进程崩溃冒充行为测试成功。程序退出码、具体失败与正常通过日志均保留可审查的含义。

另行复核的范围和结果见[独立代码核查记录](independent-review/review.zh-CN.md)；它与上述实现作者的验证记录分别保存。

这些小域检查不能替代一般证明。读者也不能由所有检查通过推断 Condillac 的历史主张成立，或推断真实语言借用会导致错误。
